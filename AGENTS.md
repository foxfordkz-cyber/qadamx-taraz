# Инструкции AI для Qadam Business

Qadam — голосовой учёт продаж, оплат и долгов с заявками, 3D-витриной Тараза и Flutter-модулем «Мал базар». Команда из шести человек. Помогай с назначенной задачей и сохраняй общий контракт.

## Перед работой

1. Прочитай `README.md`, `docs/PROJECT_STATUS.md`, `docs/DECISIONS.md`.
2. Прочитай своё задание из `docs/team5` и соответствующий файл `docs/handoffs`. Для изменений API или интеграции прочитай нужные разделы `docs/team5/02_ARCHITECTURE_API.md`.
3. Проверь текущую ветку, `git status` и существующие файлы. ТЗ описывает целевое поведение; оно не доказывает, что функция уже реализована. Не затирай чужие изменения.
4. Если задача задаёт роль, работай в её зоне. Общие изменения согласуй через владельца; не создавай параллельный каркас приложения. Небольшие необходимые исправления интеграции допустимы с объяснением в PR.
5. После обновления ветки перечитай изменённые инструкции, контракт и передачи работы. Не полагайся на память предыдущего чата.

## Владельцы

- `backend`: `apps/api`, миграции, AI, авторизация, серверные переменные, схемы API. Задание `03_TEAM_BACKEND.md`.
- `public-web`: `apps/web/src/features/explore`, `features/inquiry`, интеграция 3D. Задание `04_TEAM_PUBLIC_FRONTEND.md`.
- `seller-web`: `apps/web/src/app`, `shared`, `features/seller`, router, корневые web-зависимости и сборка. Задание `05_TEAM_SELLER_FRONTEND.md`.
- `ledger-web`: `features/voice`, `features/ledger`, `features/summary`. Задание `06_TEAM_LEDGER_FRONTEND.md`.
- `assets-3d`: `apps/web/public/models`, `public/previews`, manifest и источники моделей. Задание `07_TEAM_3D.md`.
- `mobile`: `apps/mobile`, Flutter «Мал базар», Supabase session и клиент общего API. Задание `09_TEAM_MOBILE.md`, контракт `packages/contracts/LIVESTOCK_API.md`. Backend остаётся в `apps/api`; магазин/membership для объявления не требуется.

Все файлы заданий лежат в `docs/team5`. Три frontend-разработчика работают в одном `apps/web`. Художник передаёт ассеты, а `public-web` подключает их к сцене.

## Технические правила

- Стек: FastAPI/Pydantic, PostgreSQL/SQLAlchemy/Alembic, Supabase Auth, Gemini через серверный адаптер; React/TypeScript/Vite, React Three Fiber. Меняй стек только при новой согласованной задаче.
- Контрактное изменение включает схемы, пример ответа и исправления затронутых клиентов. Не меняй названия/форматы полей только в своём модуле.
- Деньги — целые тиыны, `_minor`, валюта KZT. AI создаёт черновик; запись только после действия продавца. Балансы считает backend.
- Продажа требует `total_minor > 0`, `0 <= received_minor <= total_minor`; при долге обязателен клиент. Доплата не увеличивает продажи.
- Все закрытые запросы проверяют пользователя и принадлежность сущностей торговой точке. Нельзя обходить проверку, передавая произвольный business ID.
- Запись операции идемпотентна и атомарна; при погашении не допускается отрицательный остаток. Исправления сохраняют историю.
- RU/KZ, крупные мобильные действия, ручной ввод при сбое AI, обычный список при отсутствии WebGL.
- Учебные данные, условную геометрию и заглушки обозначай явно. Не выдавай мок за живой AI, партнёрство или работающий API.
- `.env`, приватные ключи, токены, настоящие клиентские долги и аудиозаписи не коммить. Храни только шаблоны переменных без значений.

## Завершение задачи

Проведи проверки, соответствующие изменению. Для кода используй реальные команды проекта; если тестов/запуска ещё нет, сообщи об этом, не придумывай успех. Не добавляй фиктивные CI-проверки.

Обнови только файл своей роли в `docs/handoffs`: сделано, пути, контракты, команды и результат проверок, ограничения, следующий шаг. Важное общее решение внеси в `docs/DECISIONS.md`. В `docs/PROJECT_STATUS.md` меняй сводку только при изменении общего состояния.

В финальном сообщении укажи результат, проверки и следующий шаг. Работа идёт в отдельной ветке; публикация и слияние следуют задаче пользователя и `CONTRIBUTING.md`. Не выполняй force push и не удаляй чужие изменения ради разрешения конфликта.
