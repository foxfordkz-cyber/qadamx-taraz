# AI-черновики: передача frontend

## Дополнение 2026-10-16: выбор провайдера только на сервере

Подготовлен серверный OpenAI-адаптер в `backend/openai-drafts` поверх PR #30; общий сервер пока остаётся Gemini/API 0.6.1. [Живые результаты, настройка и ограничения](../../docs/OPENAI_DRAFT_EVALUATION.md). Ни новый frontend/Flutter ключ, ни параметр provider в запросе не нужны. [Текущий OpenAPI](openapi.json), [JSON-примеры](examples.json) и generated.ts не меняются; ниже сохранена историческая передача первоначального AI-этапа.

Текст/аудио по-прежнему дают валидируемый черновик; неясные значения требуют уточнения, деньги записываются только отдельным подтверждением. При `AI_UNAVAILABLE`/`AI_TIMEOUT` сохранять ручной ввод. Отменённые или устаревшие ответы UI игнорирует; сервер не запускает фонового сохранения позднего AI-ответа. Это не новая гарантия идемпотентности POST drafts: при потере ответа во время COMMIT возможен неиспользованный 30-минутный черновик, но денег он не создаёт. Автоматический OpenAI fallback выключен. Полная голосовая приёмка не завершена: у новой комбинации моделей наблюдались два RU timeout после успешной STT.

## Multipart: текст или аудио

Пример для обработчика отправки текста. `businessId` взят из `/me`, `accessToken` — из действующей Supabase-сессии. При ошибке сохраняйте исходный текст и ручную форму.

```typescript
const apiBase = "http://127.0.0.1:8000/api/v1";
const form = new FormData();
form.append("text", "Продал товар на 3000 тенге, Демо Асқар заплатил 1000 тенге, остальное в долг");
form.append("locale", "ru"); // ru | kk | auto; default auto
const response = await fetch(`${apiBase}/businesses/${businessId}/drafts`, {
  method: "POST",
  headers: { Authorization: `Bearer ${accessToken}` },
  body: form,
});
const result = await response.json();
if (!response.ok) {
  // Показать result.error, оставить ручной ввод и введённые значения.
} else {
  // Показать result как редактируемый черновик; денежную запись здесь не делать.
}
```

Для аудио замените сборку `form` следующим кодом. Используйте MIME фактического файла; не переименовывайте произвольную запись в WAV.

```typescript
const form = new FormData();
form.append("audio", audioFile, audioFile.name); // File с корректным type
form.append("locale", "kk");
```

Браузер сам выставляет `Content-Type: multipart/form-data; boundary=...`; вручную этот заголовок не задавайте. Ровно одно поле `text` или `audio`, без дублирующихся полей. Текст — до 4000 символов, аудио — до 8 MiB и 30 секунд. Поддерживаются WAV, MP3, OGG/Opus, WebM, MP4/M4A, FLAC; сервер проверяет содержимое. Реальные записи браузера/телефона ещё требуют интеграционной проверки.

## Ответ с уточнением

Учебный пример `ClarificationDraftResponse` из `examples.json` (UUID и дата иллюстративные; берите фактические значения ответа):

```json
{
  "id": "40000000-0000-4000-8000-000000000001",
  "transcript": "Тауарды үш мың теңгеге саттым",
  "kind": "sale",
  "customer_query": null,
  "customer_candidates": [],
  "sale_candidates": [],
  "description": "Товар",
  "total_minor": 300000,
  "received_minor": null,
  "amount_minor": null,
  "missing_fields": ["received_minor", "customer_id"],
  "questions": ["Қазір қанша төленді?", "Клиентті таңдаңыз немесе қосыңыз."],
  "expires_at": "2026-10-15T10:30:00Z"
}
```

`null` означает неизвестное значение, а не нулевую оплату. Покажите `questions` и поля из `missing_fields`, предложите явный выбор клиента. Клиентов можно получить/создать через `GET/POST /businesses/{id}/customers`. Единственного кандидата тоже показывайте продавцу на проверку. Для погашения продавец всегда выбирает открытую продажу (`sale_id`); кандидаты ограничены 20, полный список — `GET /businesses/{id}/operations?outstanding_only=true&customer_id=...` с пагинацией.

Уточнение происходит в редактируемой форме frontend. Отдельного PATCH/GET черновика нет. После ввода недостающих значений отправляется полное тело операции с исходным `draft_id`. При `kind=unknown` продавец выбирает тип. Значения `_minor` — целые тиыны: 3000 ₸ = 300000. Клиент обязателен, если `received_minor < total_minor`; при полной оплате его можно не задавать.

## Явное подтверждение

Только отдельное действие продавца вызывает `POST /api/v1/businesses/{businessId}/operations`. Заголовки:

```http
Authorization: Bearer <Supabase access_token>
Content-Type: application/json
Idempotency-Key: <сохранённый ключ этой попытки>
```

Тело после уточнения и проверки (пример `ConfirmedSaleCreate`):

```json
{
  "kind": "sale",
  "draft_id": "40000000-0000-4000-8000-000000000001",
  "customer_id": "f156d6e2-d862-5d02-bcbe-0fcbff9cb8a0",
  "description": "Учебная продажа",
  "total_minor": 300000,
  "received_minor": 100000
}
```

Подставляйте `draft_id=result.id`, выбранного клиента текущей точки и поля проверенной формы. `Idempotency-Key` создаётся один раз (например, `crypto.randomUUID()`) и сохраняется вместе с точным телом запроса до однозначного результата. При сетевом сбое/таймауте повторяйте то же тело и ключ; не генерируйте новый ключ при каждом fetch. При смене пользователя/точки не переносите незавершённое подтверждение в другой контекст. При неопределённом результате подтверждения сначала разрешите повтор с тем же ключом, прежде чем создавать отдельную ручную продажу.

Успех — HTTP 200, `OperationResponse`: `operation`, `sale_balance_minor`, `customer_balance_minor`, `created_at`. Для примера долг продажи — `200000`; баланс клиента может включать другие долги. Точное тело ответа есть в `examples.json`. После успеха обновите `GET /businesses/{id}/operations`, клиентов и `GET /businesses/{id}/summary`. Summary использует день в `Asia/Almaty`, необязательный параметр `date=YYYY-MM-DD`; `outstanding_minor` — общий остаток долга, а не только долги за выбранный день.

Для погашения используется тот же endpoint: `kind=repayment`, `draft_id`, выбранный `sale_id`, `amount_minor` и `description`. Схема — `RepaymentCreate`, пример черновика — `RepaymentDraftResponse`; погашение не увеличивает продажи.

## Срок, повторы и ошибки

Черновик принадлежит автору и торговой точке, действует 30 минут. Таймер UI — подсказка; окончательное решение принимает сервер. Потребление черновика, запись операции и идемпотентный ответ фиксируются одной транзакцией.

| Результат | Действие frontend |
|---|---|
| 200 при повторе исходного ключа/тела | Прежний результат, не добавлять вторую строку локально |
| 409 `DRAFT_USED` при новом ключе | Черновик уже использован; обновить журнал |
| 409 `DRAFT_EXPIRED` | Предложить новый черновик либо проверенный ручной ввод |
| 409 `IDEMPOTENCY_CONFLICT` | Ключ связан с другим телом; не повторять изменённое тело вслепую |
| 409 `BALANCE_CHANGED` | Обновить остаток выбранной продажи и уточнить оплату |
| 404 | Чужой/недоступный объект, в том числе черновик другого автора |
| 401 | Обновить сессию или запросить вход |
| 413 / 415 / 422 | Показать ошибку размера/формата/валидации и сохранить форму |
| 503 `AI_UNAVAILABLE` / 504 `AI_TIMEOUT` | Сохранить ручной ввод; AI не записал денежную операцию |

Ошибка имеет форму `{"error":{"code":"...","message":"...","fields":{}},"request_id":"..."}`. Неизвестные ошибки также не должны очищать форму. Ручная запись использует прежний endpoint и `draft_id=null` после отдельного подтверждения продавцом.

## Что проверено

- Локальная PostgreSQL: **165 passed**, включая авторство/точку, TTL, конкурентное подтверждение, rollback и ошибки AI; Gemini в этих тестах заменён заглушкой.
- Supabase qadam-demo: `0003_drafts` применена, прямые права anon/authenticated закрыты, схема совпадает с моделями. Очищающие тесты не запускались.
- Настоящие HTTP/JWT/JWKS и живой `gemini-3.6-flash`: RU-текст → черновик → подтверждение → журнал → summary прошли. Одна помеченная учебная продажа в `mart-demo-food`: 3000 ₸, оплачено 1000 ₸, долг 2000 ₸. Повтор не создал вторую продажу, доступ B запрещён. Отдельный перезапуск API подтвердил replay.
- Ранее живой Gemini прошёл 11 RU/KZ/mixed текстовых примеров и синтетическое RU-аудио. Полный набор 20/20, реальное KZ-аудио, UI/телефон и HTTPS-деплой пока не подтверждены.
