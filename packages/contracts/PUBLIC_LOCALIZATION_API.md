# RU/KK публичные данные — issue #69

Контракт публикуется до реализации. База86ca9af; additive migration0007_public_i18n.
Никаких изменений UUID/slug, финансов, customers, memberships или автоматического перевода.

## Запросы и ответы

Опциональный `lang=ru|kk` у GET `/api/v1/venues`, `/businesses`, `/businesses/{slug}`
и авторизованного `/me`. Метка кнопки KZ соответствует языковому коду **kk**.
Неверный/пустой lang —422; Accept-Language не используется. Кэш клиента должен включать lang.

Ответ сохраняет существующие поля и добавляет nullable объекты:

- Venue: `name_i18n`, `address_label_i18n`;
- PublicBusiness/Shop: `name_i18n`, `description_i18n`;
- CatalogResponse и BusinessMembership: `name_i18n`.

Каждый объект: `{ "ru": "..." | null, "kk": "..." | null }` или null.
Без lang все старые строки остаются исходными. При lang поле `name`/`description`/
`address_label` получает соответствующий непустой перевод, иначе **исходную строку**.
Нет подстановки другого языка, транслитерации или машинного перевода на запросе.
Переводы независимы по полям: название может иметь kk, описание — исходное.
Исходные строки в БД не перезаписываются. UUID/slug, category, деньги/available/is_demo
и membership scope не зависят от языка. Поиск q пока ищет исходное name как раньше;
сортировка/курсор по UUID не меняются.

Пример учебного предложения (требует языкового review, не объявлено проверенным):

```http
GET /api/v1/businesses/kaikarmet-demo-food?lang=kk
```
```json
{
  "name": "Демо Кайкармет — Азық-түлік",
  "name_i18n": {"ru": "Демо Кайкармет — Продукты", "kk": "Демо Кайкармет — Азық-түлік"},
  "description": "Оқу сауда нүктесі, алаңның расталған серіктесі емес.",
  "description_i18n": {"ru": "Учебная точка, не подтверждённый партнёр площадки.", "kk": "Оқу сауда нүктесі, алаңның расталған серіктесі емес."},
  "is_demo": true
}
```
Это фрагмент ShopResponse: остальные старые поля сохраняются. При `lang=ru` название
«Демо Кайкармет — Продукты». Без lang — прежнее «Демо Кайкармет food».
При отсутствии kk остаётся исходная строка; i18n не содержит выдуманного значения.
Полные валидируемые примеры будут в examples.json.

## Данные и rollout

0007 добавляет nullable JSONB columns с ограничением ru/kk и непустых строк.
Миграция не заполняет переводы. Existing RLS/запрет прямого доступа сохраняется.
Сначала backup/restore и миграция, затем backend, проверка legacy+lang, затем web/Flutter.
Старые web/Flutter продолжают читать прежние поля; новые могут передавать lang и читать
уже локализованные строки. generated.ts обновляется; UI делает владелец клиента.
`/me` остаётся membership-only. Переводы пользователей/клиентов/объявлений не добавляются.

Учебные тексты — отдельный reviewable JSON manifest, первоначально `reviewed=false`.
Применение отдельной утилитой, не seed: только явный allowlist известных demo UUID,
is_demo=true, точное совпадение исходных шаблонных полей, пустые i18n columns.
Изменённые продавцом записи/существующие переводы пропускаются. Manifest сначала
проверяет носитель языка, выставляет reviewed=true; dry-run по умолчанию, apply отдельно.
Сохранить план/backup перед apply; база и memberships вне scope утилиты.

Откат приложения к0.6.2 допускает оставить nullable columns и переводы. Не выполнять
downgrade на общей БД: он удалит i18n. При отмене ошибочного data patch восстанавливать
только i18n затронутых UUID из backup после сравнения текущих значений; не трогать исходные строки.
В рамках PR общая БД/seed/Render не изменяются.
