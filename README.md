# Qadam Business — backend, авторизация және дауыс есебі

## Ашық витрина және 3D

Басты `/` бет тіркелусіз ашылады: **MART, Кайкармет, Ауыл Береке**, алаңды 3D/карточкадан таңдау, санат/іздеу, дүкеннің оқу каталогы және серверге өтінім. Қазақша/орысша тіл ауысады. Геометрия шартты, нүктелер оқу мақсатында берілген.

Өтінімді өз кабинетіңізде тексеру: **Кабинет → Витрина / Өтінімдер → Менің витринам**. Атауы, алаңы, санаты, сипаттамасын толтырып жариялаңыз. **Менің ашық парақшам** сілтемесінен тест өтінімін жіберіңіз; кабинетте жаңартқанда ол көрінеді және сервер қайта іске қосылса да сақталады. Бастапқы тоғыз оқу нүктесінде нақты сатушы жоқ — олардың формасы осыны ашық көрсетеді.

Маршруттар: `/`, `/venues/mart`, `/venues/kaikarmet`, `/venues/auyl-bereke`, `/shops/:slug`, `/seller/inquiries`, `/seller/ai`. Сатушы кабинеті аккаунт талап етеді; ашық каталог жеке клиенттер мен қарыздарды көрсетпейді. Өтінім сәтті жауап алғанша мәтінді сақтайды, желілік қайталауда сол UUID қолданады.

`node scripts/check-models.mjs` GLB жүктегішін және модель бюджеттерін тексереді. Нәтижелер, толық қабылдау сценарийі және әлі орындалмаған нақты телефон/визуалды тексерулер: [public-web handoff](docs/handoffs/public-web.md). Витрина қолданыстағы `src/` және `backend/` ішінде; екінші frontend жоқ.

Қазақша React интерфейсі + FastAPI сервері. Клиенттер, ақша операциялары және аккаунттар енді браузерде емес, сервердің SQLite базасында сақталады. Gemini интеграциясы нақты серверлік SDK арқылы орындалады; кілт болмаса AI жауабы ойдан жасалмайды.

## 1. Іске қосу (Windows)

Осы README тұрған `qadamx-ledger-starter` бумасында:

```powershell
npm.cmd install
npm.cmd run setup
npm.cmd run dev
```

Python 3.10+ және Node.js 22 қажет. `setup` жобаның `.venv` ортасына backend пакеттерін орнатады. `dev` API мен интерфейсті бірге іске қосады.

- Сайт: http://127.0.0.1:5173
- API құжаттамасы: http://127.0.0.1:8000/docs
- Сервер күйі: http://127.0.0.1:8000/api/v1/health
- Тоқтату: терминалда Ctrl+C.

Сайттан **Тіркелу** таңдаңыз, дүкен атауын, email және кемінде 10 таңбалық құпиясөзді енгізіңіз. Дайын ортақ құпиясөз жоқ. Әр жаңа аккаунтқа жеке дүкен жасалады. Email растау және email арқылы парольді қалпына келтіру әзірге қосылмаған.

## 2. Нақты AI және дауыс тану

1. [Google AI Studio](https://aistudio.google.com/api-keys) ішінде Gemini API кілтін жасаңыз. [Ресми нұсқаулық](https://ai.google.dev/gemini-api/docs/api-key).
2. `backend/.env` файлын ашыңыз (`setup` оны шаблоннан жасайды).
3. Бос мәнге өз кілтіңізді қойыңыз:

```dotenv
AI_API_KEY=өз_кілтіңіз
AI_MODEL=gemini-3.5-flash-lite
AI_FALLBACK_MODEL=gemini-3.8-flash
```

4. Серверді Ctrl+C арқылы тоқтатып, `npm.cmd run dev` арқылы қайта қосыңыз.
5. Сайтқа кіріп, **AI көмекшісі** бөлімін ашыңыз. Мәтін жазып **AI арқылы талдау** басыңыз немесе микрофонмен жазып **Тоқтату және талдау** таңдаңыз. AI черновигін тексеріп, **өзіңіз растаңыз**.

AI панелінің мүмкіндіктері:

- Қазақша, орысша немесе автоматты тіл таңдау; төрт түрлі сатылым/төлем мысалы.
- Микрофон таңдау және дыбыс деңгейі; жазуды кідірту/жалғастыру; алдымен тыңдау немесе бірден талдау.
- Аудиофайлды сүйреп тастау; 8 МБ/30 секунд шектеуі. Браузердегі жазу шамамен 29 секундта тоқтайды — кодекке қор қалады.
- Талдауды күту уақытын көру және тоқтату. Тоқтату енгізуді өшірмейді, кеш келген жауап жаңа жазбаны алмастырмайды. Провайдерге жіберілген сұрау оның жағында аяқталуы мүмкін.
- AI черновигіндегі **AI-ға нақтылау немесе мәтінді түзету** арқылы сома/төлемді нақтылап қайта талдау. Бұл өздігінен ақша операциясын жасамайды.
- Микрофон рұқсатын күту кезінде бас тарту; рұқсат, құрылғы жоқтығы және құрылғы ажыратылуы туралы бөлек түсіндірме.

Модель атауы env арқылы ауысады; аккаунтыңызға қолжетімді [Gemini модельдерін](https://ai.google.dev/gemini-api/docs/models) пайдаланыңыз. API квотасы мен есепшоты өз Google жобаңызға байланысты. Gemini қолданбасына жазылу API баптауының орнына жүрмейді.

Кілтті чатқа, Git-ке немесе frontend-тегі `VITE_` айнымалысына жазбаңыз. `backend/.env` Git пен дайын ZIP архивінен шығарылған. Кілт браузерге жіберілмейді. `/me` тек `ai_configured: true/false` күйін көрсетеді.

Дауыс жолы: браузер MediaRecorder → FastAPI → нақты аудионы декодтау/ұзақтығын тексеру → моно WAV → Gemini → Pydantic тексеруі → черновик. Ең көбі 30 секунд және 8 МБ. WebM, MP4/M4A, Ogg, WAV, MP3, FLAC, AAC қолдау табады, бірақ файл мазмұны шынымен декодталуы керек. Бастапқы аудио тұрақты сақталмайды: multipart өңдеуі уақытша файл қолдануы мүмкін, ол сұраудан кейін жабылады. Черновиктің мәтіні серверде сақталады. [Gemini аудио құжаттамасы](https://ai.google.dev/gemini-api/docs/generate-content/audio).

Қазақша, орысша және аралас сөйлемдер қолданылады. Төленгені айтылмаса, AI толық төлемді автоматты түрде қоймайды. Клиент пен сатылым UUID-ларын тек сервер өз базасынан ұсынады. Бірнеше аттас клиент немесе бірнеше қарыз болса, таңдау пайдаланушыда қалады. Қате/timeout кезінде қолмен енгізуге болады.

## 3. Тексеру сценарийі

1. Клиенттер → Асқар қосу.
2. Жаңа жазба → қолмен енгізу: сатылым **3000 ₸**, алынғаны **1000 ₸**, клиент Асқар.
3. Растаған соң қарыз **2000 ₸**.
4. Қарыздар → Төлем қабылдау → **500 ₸** → растау.
5. Күн қорытындысы: сатылым **3000 ₸**, түскені **1500 ₸**, қарыз **1500 ₸**.
6. Бетті немесе серверді қайта іске қосыңыз — жазбалар база файлында қалады.
7. Қате төлемді тарихтан қайтарыңыз. Түзету жаңа операция болады, бастапқы жазба жойылмайды. Қосымша төлемдері бар сатылымды қайтармас бұрын сол төлемдерді қайтару қажет.

## 4. Серверлік кепілдіктер

- Ақша бүтін тиынмен есептеледі; float, теріс сома, нөлдік сатылым және артық төлем қабылданбайды.
- SQLite `BEGIN IMMEDIATE` транзакциясы қалдықты оқымай тұрып жазуды кезекке қояды: қатар келген екі төлем теріс қалдық жасамайды.
- Операция/түзету, черновикті пайдалану және `Idempotency-Key` нәтижесі бір транзакцияда сақталады. Бір кілт пен бір дене — бұрынғы нәтиже; басқа дене — 409.
- Черновик 30 минут жарамды және бір рет пайдаланылады. AI ақша журналын өзі өзгертпейді.
- Құпиясөз Argon2 арқылы хэштеледі. 12 сағаттық сеанс кездейсоқ токеннен тұрады; базада токеннің хэші сақталады. Cookie: HttpOnly, SameSite=Strict. Шыққанда сервер сеансты жояды.
- Әр сұрауда аккаунттың дүкенге, клиентке, сатылымға және черновикке қолжетімділігі тексеріледі.
- Origin тексеруі, кіруге және AI шақыруына лимит бар. Сұрау өлшемі ағынмен шектеледі.
- Сеанс аяқталса, интерфейс қайта кіру терезесін ашады. Сол аккаунтпен қайта кіргенде ашық форма сақталады.
- Нәтижесі белгісіз сақтау сұрауының кілті/денесі sessionStorage-де аккаунт бойынша бөлек сақталады. Қайталау сол сұрауды қайта жібереді.

## 5. Баптау және файлдар

`backend/.env`:

```dotenv
AI_API_KEY=
AI_MODEL=gemini-3.5-flash-lite
AI_FALLBACK_MODEL=gemini-3.8-flash
ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
COOKIE_SECURE=false
DATABASE_PATH=data/qadam.sqlite3
ALLOW_REGISTRATION=true
```

Деректер: `backend/data/qadam.sqlite3`. Серверді тоқтатқаннан кейін `backend/data` бумасын резервтік көшірмеге сақтаңыз. Базаны жою барлық аккаунт пен операцияны жояды. Ол әрекет автоматты түрде орындалмайды.

Frontend `.env` міндетті емес. Әдепкіде `/api/v1` Vite proxy арқылы localhost:8000 серверіне өтеді. Оқу режимі керек болса, тек frontend `.env` ішіне `VITE_DEMO_MODE=true` қойыңыз. Оқу режимінің бұрынғы localStorage деректері сервер базасына автоматты көшірілмейді.

Негізгі файлдар:

- `backend/app.py`: авторизация, серверлік API, құқықтар, транзакциялар.
- `backend/db.py`: SQLite схемасы, қосылу және транзакциялар.
- `backend/schemas.py`: енгізу және AI жауаптарының валидациясы.
- `backend/ai.py`: аудио түрлендіру және Gemini адаптері.
- `src/Auth.jsx`: тіркелу, кіру, шығу, сеансты қалпына келтіру.
- `src/api.js`: cookie арқылы API және аккаунтқа тиесілі pending сұраулар.
- `src/features/voice`, `ledger`, `summary`: сатушы интерфейсі.
- `scripts/dev.mjs`: екі серверді бірге іске қосу/тоқтату.

## 6. Тесттер

AI байланысын нақты Gemini сұрауымен тексеру (ақша журналына жазбайды):

```powershell
.\.venv\Scripts\python.exe -m backend.check_ai
```

`AI_MODEL` — негізгі модель, `AI_FALLBACK_MODEL` — уақытша сервер қатесі,
timeout немесе модель табылмаған кезде қолданылатын резервтік модель.
Уақытша ақауда ең көбі үш әрекет жасалады: негізгі, резервтік, негізгі модель.
Жалпы күту уақыты 25 секундтан аспайды. Жарамсыз жауап бір рет қайта талданады. Кілт не квота қатесінде
қайта сұрау жіберілмейді. `.env` өзгергеннен кейін `npm.cmd run dev` қайта іске қосыңыз.

AI жауап бермесе, қолмен толтыру бірден ашылады. Бастапқы мәтін мен аудио осы бетте қалады;
«Қайта талдау» сол енгізуді қайта жібереді. Мәтін мен толтырылған өрістер осы браузер
қойындысының sessionStorage ішінде аккаунт бойынша сақталады және бет жаңарғанда қалпына келеді.
Аудио тек бет жадында: бетті жаңартқанда аудиофайлды қайта таңдау керек.
Браузер сақтау орнын бұғаттаса, енгізу бет жадында ғана қалады.

Толық нақты AI → растау → төлем → қорытынды тексеруі жеке уақытша база қолданады:

```powershell
.\.venv\Scripts\python.exe -m backend.check_flow
```

`backend.check_ai` және `backend.check_flow` үшін `--audio sample.wav` қосуға болады.
Сынақ мәтіні/аудиосы: 3000 ₸ сатылым, 1000 ₸ төлем. Бұл командалар нақты Gemini сұрауын
жібереді; `check_flow` пайдаланушы базасын өзгертпейді.

```powershell
npm.cmd test
.\.venv\Scripts\python.exe -m pytest backend -q
npm.cmd run build
```

Backend тесттері уақытша жеке SQLite базаларымен жұмыс істейді. Нақты Gemini шақырылмайды: кілтсіз қате және тесттік провайдер жауаптары арқылы интеграция шекарасы тексеріледі. Аудио тесттері жасанды дыбыссыз WAV қолданады, олар нақты адам сөйлеуін танудың дәлелі емес.

Нақты орындалған тексерулер мен шектеулер `VERIFICATION.md` ішінде жазылады.

## 7. Жария орналастыру шекарасы

Бұл компьютерде іске қосылатын бір серверлі нұсқа. Бастапқы жоспардағы Supabase Auth/PostgreSQL орнына сыртқы аккаунтсыз іске қосылу үшін жергілікті Argon2/session авторизациясы және SQLite қолданылды. API ақша пішіндері сақталды, frontend енді JWT орнына HttpOnly cookie қолданады.

Интернетке орналастырғанда frontend пен `/api` бір HTTPS доменде болуы, `COOKIE_SECURE=true`, нақты `ALLOWED_ORIGINS`, тұрақты диск және резервтік көшірме қажет. Аккаунттарды ашқан соң қажет болмаса `ALLOW_REGISTRATION=false` қойыңыз. Көп серверлік масштабтау үшін PostgreSQL, орталық rate limiter және бөлек көшіру жұмысы керек. Бұл нұсқаны уақытша дискісі бар серверге деректер сақталады деп орналастыруға болмайды.

Жария 3D витрина, тауар қоймасы және өтінім модулі осы тапсырмаға кірмейді; жаңа өтінімдер саны әзірге 0.
