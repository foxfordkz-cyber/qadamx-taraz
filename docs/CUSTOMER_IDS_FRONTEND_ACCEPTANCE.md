## Review и флаг production

Блокирующих дефектов #63/#65 не найдено. Lookup передаёт только повторяющиеся
`ids=UUID&ids=UUID`, без q/cursor/limit. Набор нормализуется, дедуплицируется,
разбивается по 100; пустой набор не вызывает HTTP. Ответ проверяется по business,
запрошенным IDs, уникальности, целому серверному балансу и null cursor.
Чужой/отсутствующий клиент не подменяется другой строкой.

Query keys содержат auth scope, business и пакет IDs. AbortSignal и смена scope
не дают позднему ответу прежней точки/пользователя появиться в новом контексте.
Суммы строк остаются серверными и видимы при сбое загрузки имён. Итог выбранного
клиента берётся из `balance_minor`, а не суммирования видимой страницы.
Успешная запись инвалидирует общий prefix текущих scope/business, включая новый lookup.
Customer recovery coordinator и транспорт создания клиента не изменены.

`vercel.json` теперь вызывает **`node scripts/build-hosted.mjs`**. Этот скрипт
проверяет прежние публичные настройки и фиксирует **VITE_CUSTOMER_IDS_ENABLED=true**
в окружении компиляции TypeScript/Vite. Это намеренное включение после HTTPS gate
backend: устаревшее false/отсутствующая переменная панели не выключат функцию молча.
Сборка проверена даже при входном false; браузер отправил пять настоящих ids GET.
Обычный локальный `npm run build/dev` сохраняет opt-in через переменную, default false.

Действующий production ещё не содержит PR65. Значение runtime-флага нельзя
подтвердить состоянием ветки/панели: после будущего deployment нужно увидеть
реальные GET с ids в опубликованном web. URL API остаётся
`https://qadamx-taraz.onrender.com/api/v1`.
