Серверная конфигурация не менялась.

1. Настоящий login A, `/me`, 6 доступных точек. В CustomerPicker продажи создан один явно учебный клиент.
2. Тестовый перехват сначала выполнил настоящий POST, получил HTTP201 с UUID, **после этого** скрыл ответ от браузера. Браузер показал unknown; production API не ломался. Последующие GET lookup временно получали503 только в этом тестовом браузере, чтобы удержать состояние для перехода/reload.
3. Picker → страница клиентов сохраняет ключ. Reload сохраняет маркер; автоматического нового POST нет. Если после полной навигации выбрана первая точка списка, требуется снова выбрать нужную: текущий BusinessProvider не хранит выбор между полной загрузкой страниц.
4. Настоящий GET recovery (вне перехвата) вернул completed и тот же UUID. Один явный API POST с **прежними ключом и точным телом** вернул тот же201/snapshot. По уникальному учебному имени на сервере ровно один клиент. UI-повтор при временно недоступном lookup не обходит recovery новым ключом.
