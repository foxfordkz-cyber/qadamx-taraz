## Что нужно backend для KZ

- Публичные ответы сейчас отдают одно поле `name` (и `description`). Витрина уже умеет показывать `name_kk`, если оно есть в ответе (`features/explore/i18n.ts`, функция `name`), но в OpenAPI и моделях API этого поля нет. Варианты для решения backend: добавить nullable `name_kk` / `description_kk` (контрактное изменение: схемы, примеры, `generated.ts`, затронутые клиенты) либо оставить RU-названия и не показывать KZ-версии.
- Кабинет продавца берёт название точки из `/me`; при добавлении KZ-поля его тоже нужно отдать там.
- Порядок: правка демо-строк — только в выделенной demo-БД или отдельной проверенной миграцией данных; повторный seed по общей БД не запускать (seed insert-only и существующие строки не обновит).

Казахские формулировки стоит перепроверить носителю языка в команде перед применением.
