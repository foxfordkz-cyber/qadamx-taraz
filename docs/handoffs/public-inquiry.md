## Интерфейс и исправления review

`import InquiryForm from "../inquiry/InquiryForm"`; props `businessId: string`, `businessName?: string`. ShopPage передаёт **настоящее `b.name`** и сохраняет `key={b.id}`. Внутренняя граница формы дополнительно keyed по businessId: смена получателя создаёт отдельное состояние, поздний ответ старой формы игнорируется после unmount. Значение businessName не используется для API-маршрута, только для подписи.

POST `/businesses/{UUID}/inquiries`: неизменный контракт API0.6.2 — `visitor_name`, `contact`, `message`, UUID `client_request_id`; ответ `{id, created_at}`. Никаких денежных операций или автоматического создания клиентов. Контакт произвольный, а не только телефон. Поля trim и лимиты100/200/2000 **Unicode code points**, как Pydantic. HTML maxLength учитывает возможные UTF-16 пары; ошибки показывает общий RU/KZ locale.

Найден и исправлен дефект автора: unknown→последующий4xx сбрасывал pending и создавал новый key. Теперь любая неизвестная попытка закрепляет исходные key/body до валидной квитанции; последующие400/401/403/404/409/422/429 не снимают защиту. Поля заблокированы, повтор только явный с тем же телом. Лишь первоначальный однозначный4xx без предшествующего unknown разрешает исправление полей/новое намерение. Синхронный lock блокирует двойной submit. Нет автоматических повторов.

Исходники: `apps/web/src/features/inquiry/InquiryForm.tsx`, подключение `features/explore/ShopPage.tsx`, тесты `src/test/inquiry.test.tsx`. Общие Auth/recovery/AI/Analytics/OpenAPI/GLB не менялись.

## Границы и следующий шаг

Состояние заявки сейчас живёт в памяти конкретной формы: закрытие страницы или переход в другой магазин его не сохраняет. Это не customer recovery с durable storage/GET receipt; не обещать восстановление публичной заявки после reload. В пределах открытой формы неизвестный intent никогда не заменяется после4xx. Автоматической повторной отправки при возврате в магазин нет. Если требуется durable inquiry recovery, согласовать отдельный контракт хранения контакта/текста и восстановления; не сохранять PII в localStorage незаметно.

Проверки поздних ответов и неизвестный→4xx — изолированные заглушки; production API специально не ломался. Мобильные ширины в Chrome, не физический телефон. Общая передача/фактический deployment — [INQUIRY_RELEASE_REVIEW](../INQUIRY_RELEASE_REVIEW.md).
