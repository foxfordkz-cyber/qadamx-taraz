# Передача публичной витрины

Дата: 2026-10-16. Ветка: `frontend/aidana-public-showcase`, основана на работающем `feature/aidana-ai-assistant`. В `main` не слито. Отдельный frontend не создавался.

## Реализовано

- Открытые `/`, `/venues/:slug`, `/shops/:slug` в существующем React/Vite. Авторизация требуется только `/seller/*`. AI, голос и журнал сохранены.
- RU/KZ, карточки MART / Кайкармет / Ауыл Береке, клавиатурные ссылки, категории/поиск в URL, состояния загрузки/ошибки/пустого результата/404.
- Обзор из лёгких блоков; GLB загружается только для выбранной площадки. Силуэт, HTML-метка и карточка ведут на одинаковый URL. Hotspot сверяется с API одновременно по slug и ID; неизвестные/отфильтрованные точки не показываются.
- Плавная камера, мгновенный переход при reduced motion, ограничения zoom и полярного угла; «Общий вид» возвращает камеру к целой модели. К трём площадкам ведут хлебные крошки.
- Render-on-demand, DPR максимум 1.5, без теней/bloom/внешних текстур. Геометрия/материалы освобождаются при смене модели; опоздавшая загрузка тоже освобождается. Управление 3D включается кнопкой; по умолчанию доступен вертикальный скролл.
- При отсутствии WebGL, ошибке JS/GLB и потере контекста остаются карточки и форма. Ошибка GLB оставляет блоковую геометрию.
- Учебный каталог из API, цена KZT или «Уточнить», без обещания наличия. После заявки — серверный номер.
- Валидация контакта/длины на клиенте и сервере. До отправки полный запрос с UUID сохраняется в sessionStorage; повтор после сбоя/перезагрузки использует прежний ID и тело. Двойное нажатие блокируется. После подтверждения контакт удаляется из браузерного черновика.
- Обращения хранятся в той же SQLite БД. `/seller/inquiries`: явная публикация собственной учебной витрины, публичная ссылка, приватные входящие, статусы, обновление. Каждый закрытый метод проверяет владельца. Публикация не раскрывает клиентов, долги или данные аккаунта.
- Девять исходных учебных точек не имеют реального продавца: форма явно объясняет учебное сохранение и предлагает тестовый контакт. Для полного пути до кабинета следует публиковать собственную точку. Присвоение общих или чужих точек невозможно.

## Ручной приёмочный сценарий

1. `npm.cmd run dev`, открыть `/`; выбрать площадку карточкой и её силуэтом.
2. Выбрать hotspot и соответствующую карточку: проверить один `/shops/{slug}`. Проверить поиск, назад/вперёд и RU/KZ.
3. Войти своим аккаунтом в `/seller/inquiries`, открыть «Моя витрина», заполнить название/площадку/категорию/описание и сохранить с публикацией.
4. Открыть публичную ссылку без авторизации; отправить синтетические имя, `visitor@example.test` и вопрос. Получить номер.
5. Обновить inbox владельца; проверить номер, текст, контакт; изменить статус. Обновить страницу/перезапустить API — обращение остаётся. Другой аккаунт не получает его.
6. Проверить 360 px, клавиатуру, отключённый WebGL, недоступный GLB. На телефоне проверить вертикальный свайп до/после включения 3D, reduced motion и reset камеры.

## Ограничения и оставшаяся приёмка

- Browser runtime возвращает пустой список; Computer Use — `native pipe is unavailable`. Визуальная проверка настоящего браузера, 360 px, GPU-рендер и запись видео в этой среде **не выполнены**. DOM-тесты не выдаются за них.
- Реальный телефон не подключён: FPS, время загрузки и реальные touch-жесты не измерены. Бюджеты файлов проверены, показатели устройства не заявляются.
- GitHub содержит исходный код в отдельной ветке; хостинг сайта не настраивался. Для размещения нужны HTTPS, SPA fallback на `index.html`, `/api` на FastAPI, постоянный диск БД и корректный `ALLOWED_ORIGINS`.
- Оплата, склад, карта всего города, реальная внутренняя навигация и отдельный AI-поиск исключены из задания.
