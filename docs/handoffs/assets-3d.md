# Передача работы 3D

Роль: assets-3d. Ветка: `assets/venue-models`. Последнее обновление: 2026-10-15.

Три модели, превью и manifest готовы для передачи public-web. Экспорт и загрузка в самостоятельном desktop-просмотрщике проверены; приёмка в настоящем приложении и на реальном телефоне остаётся открытой.

## Сделано

Переработаны все три модели после визуальной проверки фотографий, 2ГИС, панорам и спутниковых видов. MART теперь вытянутый асимметричный комплекс со стрельчатым входом и четырьмя малыми глухими арками; Кайкармет — длинный синий фасад и связанная крытая рыночная часть; Ауыл Береке — западный вход с конями, крупный правый корпус, открытый левый двор и длинные ряды. Подробные источники, даты, наблюдения и исключённые ложные совпадения записаны в assets/venues/research/.

Все площадки имеют `geometry_status: "reference_based"` и `conceptual_scale: true`. Это реконструкция по изображениям, не подтверждённая копия 1:1. Размеры оценочные; крыши, задние стороны и некоторые соединения упрощены. Ауыл Береке охватывает вход и прилегающую часть, а не весь торговый квартал. Поле reconstruction отделяет подтверждённые признаки от оценочных. Учебные точки не задают маршрут к реальному продавцу.

Независимая проверка Astra Ultra выявила завышенный проём MART и вложенную подпись Ауыл Береке; оба замечания исправлены. [Запись проверки](../../assets/venues/research/reconstruction-review.json) содержит решения и хеши финальных моделей.

## Проверки

- [Проверка договора и геометрии](../../assets/venues/validation.json), `tools/assets/validate_assets.py`: 0 ошибок, 0 предупреждений, 0 вырожденных треугольников у всех моделей. Проверены размеры файлов, данные геометрии, normals, bounds, manifest и связи с seed.
- [Независимая проверка Khronos](../../assets/venues/gltf-validation.json), `tools/assets/validate_gltf.cjs`: 0 ошибок и 0 предупреждений; SHA-256 в отчёте соответствуют итоговым GLB.
- В экспортированных GLB +Y вверх, главный фасад ориентирован к +Z; соглашение масштаба — 1 unit = 1 метр. Scale/rotation применены, масштаб положительный. Origin находится в центре основания, `minY = 0` у всех трёх площадок.
- Материалы встроены. Текстур, внешних URI, обязательных декодеров сжатия, экспортированных камер и света нет.
- В самостоятельном desktop-просмотрщике обычный `GLTFLoader` загружает все три модели; проверен выбор всех девяти hotspot. Одновременно показывается одна подробная площадка.
- [Браузерная проверка](../../assets/venues/browser-validation.json): при viewport 360 × 800 (canvas 319 × 350) загружены все три модели, все 8/8 углов bounds попадают в кадр, проверены девять hotspot; горизонтального переполнения и перекрытия круглых кнопок нет. Точки MART и Ауыл Береке разнесены в пределах учебных зон для удобного нажатия. Это узкий viewport desktop-браузера, не проверка физического телефона.
- В запасном режиме вручную открыты и декодированы все три WebP 1024 × 768, проверены девять кликов по hotspot. Возврат к 3D и сброс камеры проверены на MART. Реальная потеря WebGL-контекста и недоступные запросы ассетов не моделировались.
- После синхронизации с main корневой Vite проект собирается (`npm.cmd run build`); `npm.cmd test` — 14/14 тестов. Эта сборка сейчас содержит кабинет продавца и пока не включает публичную 3D-витрину.

## Зависимости и ограничения

`id` hotspot — стабильный идентификатор маркера из fixture; `business_slug` и дополнительный `business_id` сверены с текущим `packages/contracts/demo-seed.json`. Перед интеграцией public-web должен сопоставить их с актуальным API. `position` содержит локальные XYZ модели, а не географические координаты.

При узком viewport начальную камеру нужно отодвигать по bounds, сохраняя всю модель в кадре; пример — `fitCamera()` в просмотрщике. Названия и label_ru/label_kk из manifest следует выводить HTML-подписями; подпись Ауыл Береке явно ограничивает охват входом и рядами. В режиме без WebGL использовать `poster_url`.

Ветка синхронизирована с main 8c932dd: в корневом src/ появился кабинет продавца, но публичная 3D-витрина пока отсутствует. Пути apps/web/public сохранены по договору: корневой Vite пока не раздаёт этот каталог автоматически; public-web должен подключить его или перенести web bundle в public своей сборки. Загрузка, свет, кликабельность и fallback в настоящем React/R3F-приложении, а также производительность на реальном телефоне не проверены. FPS и мобильная скорость не измерялись.

## Следующий шаг

Public-web получает содержимое web bundle, подключает manifest и одну выбранную модель, сверяет hotspot с API и проверяет начальный кадр, освещение, переключение площадок и fallback в приложении. Затем команда выполняет проверку на реальном телефоне. Исходники `.blend` передаются отдельным архивом.
