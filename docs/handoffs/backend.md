# Передача работы backend

## Видимый вход в AI — 2026-10-16

По уточнению пользователя кнопка AI не была заметна: обработка называлась
«Жазбаны дайындау», а восстановленный ручной режим скрывал её. В `src/main.jsx`
добавлен первый пункт меню «AI көмекшісі» и `/seller/ai`. Этот вход открывает
AI-режим, сохраняя текст и поля. В `Sale.jsx` вкладка явно подписана AI,
действие называется «AI арқылы талдау», добавлена короткая инструкция.
DOM-проверка входа из сохранённого ручного режима прошла, frontend tests/build
успешны. Реальный `backend.check_flow` повторно прошёл на настроенном Gemini.

## Проверка устойчивости AI и формы — 2026-10-16

- `backend/ai.py`: до трёх транспортных попыток за общий лимит 25 секунд;
  не более одной повторной обработки невалидного ответа. Незавершённый/заблокированный
  ответ не становится черновиком, исходный текст не заменяется пересказом модели.
  Противоречивая переплата требует уточнения. Ошибки ключа/квоты не повторяются.
- Интеграция `src/features/voice`: при отказе AI открывается ручная форма с исходным
  текстом/аудио и повторной отправкой; текст и поля переживают обновление вкладки
  в sessionStorage отдельно по аккаунтам. Аудио остаётся только в памяти страницы.
  Истёкший черновик можно подтвердить вручную после повторной проверки полей.
- Запись обрабатывает пустой результат, сбой, отказ в разрешении, отмену и отсутствие
  `isTypeSupported`; дорожки освобождаются. Загрузка поддерживает пустой MIME у WAV/M4A
  и video/mp4 у аудиозаписей; реальное декодирование по-прежнему проверяет backend.
- `backend/check_flow.py` проверяет реальный AI, подтверждение, идемпотентность,
  погашение и итог в отдельной удаляемой БД. Успешно выполнен для казахского текста
  и русского синтетического аудио. Английское синтетическое аудио отдельно распознано.
- Итог: 37 backend + 32 frontend теста (включая 6 React DOM сценариев), сборка успешна.
  Тесты интерфейса: сбой AI → ручное сохранение, повтор AI, восстановление полей,
  истечение черновика, повтор аудио, сетевой обрыв сохранения с тем же ключом.
- Browser недоступен (`[]`); физический микрофон и визуальное поведение на устройстве
  не проверены. DOM-тесты не выдаются за проверку настоящего браузера.

## Исправление локального AI — 2026-10-16

В запускаемом через `scripts/dev.mjs` приложении используется `backend/app.py`,
а не архивный `apps/api`. Архивы пользователя просмотрены для сравнения;
их код не подменял текущую реализацию и базу данных.

- Реальный вызов Gemini с настроенным ключом подтвердил 503 для `gemini-3.8-flash`.
  `gemini-3.5-flash-lite` успешно разобрал казахский пример: 300000/100000 тиынов.
  Основная модель изменена в локальном `.env`, шаблоне и значении по умолчанию.
- `backend/ai.py`: один резервный вызов при 404/500/502/503/504 или timeout;
  общий предел 25 секунд, отключены скрытые SDK-повторы. Ошибки ключа, квоты и сети
  возвращают понятные сообщения без сырого ответа провайдера. Формат черновика прежний.
- `backend/check_ai.py`: реальная проверка связи на синтетическом казахском тексте,
  без создания записей. Запуск: `.venv/Scripts/python.exe -m backend.check_ai`.
- Проверки: 29 backend-тестов, 14 frontend-тестов прошли; `npm.cmd run build`
  успешно после запуска вне ограничений sandbox. Реальный AI smoke — успешно.
  Дополнительный live HTTP-тест через временную БД получил 503 от провайдера;
  повторный казахский smoke снова прошёл. Внешний сервис остаётся нестабильным.
  Запущенные web и API через Vite proxy отвечают HTTP 200 на `/` и `/api/v1/health`.
  Микрофон пользователя и распознавание его речи пока не проверены.
- Доступность внешнего Gemini зависит от нагрузки и квоты; ручной ввод сохранён.

Роль: капитан, весь backend. Обновлено: 2026-10-15. Ветка: `backend/bootstrap-api`, исходный локальный commit `ee1847a`. Первый локальный этап реализован и проверен; изменения ещё не закоммичены, не опубликованы и не слиты. PR не создавался.

## Сделано

- Прочитаны инструкции, ТЗ и контракт. Исходное рабочее дерево чистое, `apps/api` отсутствовал. Попытка `git ls-remote origin refs/heads/main` завершилась ошибкой Windows Schannel `SEC_E_NO_CREDENTIALS`; актуальность удалённого main не подтверждена, история не изменялась.
- По уточнению капитана выполнен локальный этап без подключения Supabase, Gemini и Render.
- FastAPI на Python 3.12: `/health`, `/api/v1/health`, `/docs`, `/openapi.json`; ответ health `{"status":"ok","service":"qadam-api","stage":"bootstrap"}` подтверждает только процесс. Запуск без секретов и БД.
- Pydantic 2: `SaleCreate`, `RepaymentCreate`, `DraftResponse`, `OperationResponse`, `SummaryResponse`, `InquiryCreate`, `ErrorResponse`; discriminated union `OperationCreate`. Целые тиыны, запрет строк/float/bool, переплаты, долга без клиента и лишних входных полей.
- OpenAPI и проверяемые учебные JSON-примеры экспортируются в `packages/contracts`. В `paths` только реально работающие health-маршруты; будущие операции представлены схемами, без фиктивных успешных ответов.
- Единая ошибка `{error:{code,message,fields},request_id}`, заголовок `X-Request-ID`, CORS только для явно заданных origins. Текст ошибочного ввода и исключений не отражается в 422/500.
- SQLAlchemy 2 и первая Alembic-миграция: `venues`, `businesses`, `memberships`, `catalog_items`, `customers`, отдельная схема `qadam`, ограничения и индексы; доступ `PUBLIC`/`anon`/`authenticated` отозван. Автогенерация ограничена `qadam`.
- Insert-only seed в одной транзакции: три площадки, девять точек, два синтетических владельца (6 и 3 точки), девять товаров и девять покупателей. Детерминированные UUID, конфликт по PK не изменяет существующие строки. Названия явно учебные, `is_demo=true`; slug и `geometry_status=conceptual` согласованы с примером 3D-manifest.
- `uv.lock`, `.python-version`, `.env.example` без секретов, инструкция запуска и тесты. Чужие handoff-файлы и frontend не изменялись.

## Зависимости и ограничения

Нет настроенных внешних сервисов; Docker daemon недоступен. На живом PostgreSQL миграция, повторный seed и права ещё не проверены. Для этого подготовлен opt-in тест: пустая выделенная тестовая БД, `TEST_DATABASE_URL`, `uv run pytest -q -m postgres`. SQLite не используется как замена транзакционным проверкам.

Не реализованы JWT/JWKS, проверка memberships в запросах, деньги/остатки/идемпотентность/отмены, черновики и AI, публичные каталоги, заявки и отчёты. Их HTTP-маршруты отсутствуют (404). Pydantic проверяет только форму запроса; он не подтверждает существование и принадлежность UUID или текущий остаток. Финансовые сценарии из раздела «Минимальные проверки backend» ещё не выполнялись. Seed не создаёт пользователей в Supabase Auth. HTTPS-деплоя и живого AI-вызова нет.
