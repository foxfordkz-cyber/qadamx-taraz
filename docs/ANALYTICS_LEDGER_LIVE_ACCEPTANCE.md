## Повтор подтверждения и неизвестный результат

Проверен настоящий UI retry доплаты, а не только повтор через отдельный API-клиент. Первый запрос доплаты дошёл до реального backend и был успешно записан. Проверочный браузер **один раз прервал доставку его успешного ответа** (`route.fetch` к настоящему серверу, затем transport abort); финансовые ответы не подменялись fixtures.

UI показал неизвестный результат и кнопку «Проверить результат тем же запросом». **До нажатия** выполнен read-only запрос истории: найдена ровно одна доплата с UUID выше, свежая аналитика уже отражала+500/−500. После этого нажата штатная кнопка повторной проверки. Два POST доплаты имели **одинаковые Idempotency-Key и точное тело**. Ответ200 повторил исходные operation ID и остаток; значения аналитики до/после повтора совпали. В финальной истории осталась одна доплата, а не две. Продажа отправлена одним POST и также присутствует в истории один раз.

Для возможного прерывания проверочного скрипта request key/body, ID и этапы сохранялись в игнорируемом локальном файле. Новая операция с новым ключом при неоднозначности не создавалась. Весь прогон завершился успешно с первой попытки; общая БД не откатывалась.
