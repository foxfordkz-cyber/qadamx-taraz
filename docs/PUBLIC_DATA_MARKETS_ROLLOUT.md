## Совместимость web / Flutter

| Прежний запрос / данные | После миграций и нового API |
|---|---|
| GET каталога или /me без lang | Исходные строки; membership scope прежний |
| JSON без дополнительных i18n-полей | Старые читатели продолжают использовать прежние поля; новые поля nullable |
| Старое объявление без market_id | Сохраняются ID, автор, market/market_key, цена, статус, даты и фото; market_id=null |
| GET listings/prices без market_id | Прежняя область для legacy-объявлений; формулы цен сохранены |
| Новый POST без market_id | Создаёт legacy-объявление без канонической связи |
| Новый PUT без market_id | Сохраняет уже назначенную связь; только явный null снимает её |
| Неизвестный результат старого POST/PUT | Повторять прежнее тело и ключ, не дописывать market_id даже как null |
| GET customers?ids=UUID&ids=UUID | Прежний scoped Page, порядок, лимит, серверные балансы и ошибки |
| Customer recovery | Прежние Idempotency-Key, тело, автор/точка, retention и получение результата |

Код старых web/Flutter-парсеров проверен на дополнительные поля. Это не заменяет
приёмку реально используемых сборок: перед окном зафиксировать их SHA/APK и проверить
на копии БД чтение каталога, старых объявлений, клиента по ids и recovery. Затем
повторить согласованный smoke через HTTPS после rollout. Старый Flutter не должен
терять связь при редактировании, старые pending-тела нельзя пересобирать из нового DTO.

Новые клиенты включают lang/market_id только после проверки OpenAPI на работающем
backend. Cache keys включают язык и все фильтры; при смене рынка сбрасывается cursor.
Нет verified рынка — пустое состояние, не общий список объявлений. Нет цен — null.

## Откат приложения после миграций

- Предпочтителен forward fix; nullable колонки, таблицу registry и связи оставить.
  Downgrade общей БД не является обычным откатом: он удалит переводы и market links.
- Выбрать зафиксированный прежний Live SHA **с ids и customer recovery 0.6.2**,
  а не API 0.6.1, игнорирующий Idempotency-Key. Перед окном проверить этот SHA на
  восстановленной копии с 0007/0008, сохранив сравнение записей до/после.
- До включения канонических клиентов и при пустом registry прежний код может работать
  с дополнительными колонками. Но query market_id старый код игнорирует: необходимо
  заранее отключить зависимый UI и подготовить/проверить guard с явным отказом для
  запросов market_id и /livestock/markets. Одного отката web недостаточно для APK
  и уже открытых вкладок. **Готовность такого guard пока не подтверждена.**
- Если уже появились канонические связи, обычный прежний API также не проверяет статус
  рынка в публичной ленте/detail/photos. Отключить только фильтр недостаточно: нужен
  проверенный вариант, сохраняющий новую видимость, либо защитное закрытие публичных
  livestock-чтений до forward fix. Не возвращать скрытые объявления через старый код.
- Сохранить прежние Environment/CORS; проверить health, ids, recovery и legacy-чтение.
  Восстановление всей production-БД из backup — отдельное решение, не автоматический
  rollback: оно может потерять новые записи после снимка.
