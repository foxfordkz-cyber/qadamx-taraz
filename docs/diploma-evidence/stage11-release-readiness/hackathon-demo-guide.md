# Three-minute product demonstration

Use the same actual local app and preparation as [academic guide](academic-demo-guide.md).
This is a target script, not an observed task-time comparison. Start with a fresh
synthetic point and record opening totals; do not reuse altered state without disclosure.

| Time budget | Action and spoken message |
|---|---|
|0:00–0:20|Show dashboard and OFFLINE AI · SYNTHETIC label: «Продажи и долги в одном месте; сегодня показываем локальную учебную систему»|
|0:20–0:50|Create synthetic customer; manual3000/1000 sale; explicit confirmation. «Остаток2000 рассчитывает сервер»|
|0:50–1:10|Open that debt, repay500 and confirm. Show1500; no increase in sales|
|1:10–1:50|Exact supported phrase «Продажа 1200, оплатили сразу полностью» → draft; inspect1200/1200; human confirm. «AI предлагает, продавец решает»|
|1:50–2:05|Dashboard:4200 sales /2700 receipts /1500 debt (if opening totals zero)|
|2:05–2:40|Research on seeded history:7 and30 days; point to baseline comparison and rule debt reasons. «Учебная история; риск — правила, не вероятность»|
|2:40–3:00|Show no-history state or consented feedback panel. Close with next gates: realAuth, liveAI/ASR and independent review|

Pre-open known navigation panels, but do not pre-confirm money, hide failures, fake
a microphone or substitute a video for the live app without saying so.
Show customer, partial payment, debt, repayment, draft, confirmation, dashboard,
forecast and risk; omit deeper technical digressions, not the confirmation boundary.
No growth, revenue uplift, speed advantage or model accuracy claim is supported.

If three minutes is insufficient in rehearsal, ask the presenter to extend or
reduce narration; do not publish an invented measured duration.
Current Stage11 smoke proves only the documented read-only browser route.
For a live public pitch use the same approval gates as the academic guide.
