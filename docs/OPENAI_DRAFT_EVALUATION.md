# OpenAI для черновиков: проверка 2026-10-16

Ветка `backend/openai-drafts`, база `backend/ai-runtime-diagnostics` / PR #30 (`33cb37a`), затем main `1324885`. Это отдельная задача от customer recovery PR #22. Общий API, env, CORS, preview и туннели не переключались. Миграций нет. Результат подготовлен для review; голосовой OpenAI ещё не прошёл весь контрольный набор.

## Выбор модели и конфигурация

`GET /v1/models` с ключом оплаченного проекта вернул 200 и подтвердил доступность `gpt-6-luna`, `gpt-transcribe`, `gpt-4o-mini-transcribe-2025-12-15`. Это дополнено реальными вызовами, а не только каталогом моделей.

- Извлечение: `gpt-6-luna`, Responses API, strict JSON Schema, `reasoning.effort=none`, `max_output_tokens=2048`, `store=false`, без tools/background. Модель поддерживает structured output; аудио обрабатывается отдельной транскрипцией. [Официальная модель](https://developers.openai.com/api/docs/models/gpt-6-luna), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
- Кандидат для аудио: `gpt-transcribe`, `/v1/audio/transcriptions`, `languages[]=ru` и `languages[]=kk`, нейтральный языковой prompt без эталонных сумм/имён. Исходное OGG декодируется существующим серверным кодом в WAV в памяти. [Модель](https://developers.openai.com/api/docs/models/gpt-transcribe), [транскрипция и языковые подсказки](https://developers.openai.com/api/docs/guides/speech-to-text).
- Более дешёвая `gpt-4o-mini-transcribe-2025-12-15` проверена, но не рекомендована для KZ/mixed из-за фактических ошибок. [Модель и snapshot](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe).

Проверенные стандартные цены: Luna $0.10 input / $0.50 output за миллион токенов; mini transcription $1.25 input / $5 output за миллион токенов, ориентир $0.003/мин; gpt-transcribe $0.0045/мин. Это не фиксированная цена будущих вызовов: пересверять при смене модели. [Официальные цены](https://developers.openai.com/api/docs/pricing).

Только в игнорируемом **серверном** env отдельного проверочного запуска:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=
OPENAI_MODEL=gpt-6-luna
OPENAI_TRANSCRIPTION_MODEL=gpt-transcribe
AI_FALLBACK_OPENAI=false
AI_PRIMARY_TIMEOUT_SECONDS=8
```

Ключ заполнить локально; этот пример не содержит секрета. Отсутствующая настройка даёт существующий `503 AI_UNAVAILABLE`. По умолчанию `.env.example` оставляет `AI_PROVIDER=gemini`. Ключи/модель не нужны frontend или Flutter. Общий `.env` в ходе реализации не редактировался.

## Живые проверки OpenAI

Все платные вызовы шли через новый серверный адаптер с настоящим проектным ключом. В этих пробах БД не подключалась: **0 новых клиентов, 0 сохранённых черновиков, 0 денежных операций**. Черновик здесь означает валидированный результат извлечения, не запись в таблице. Весь UI → HTTP → сохранение → подтверждение для OpenAI ещё не принимался.

Шесть синтетических текстов: RU, KZ, mixed с частичной оплатой; неизвестная оплата; два неоднозначных имени; погашение старого долга. **6/6** совпали по ожидаемым полям; неизвестная оплата и неоднозначный клиент вернули `null`. Длительность 2.282–6.625 с, оценка стоимости $0.0007472. Деньги в целых тиынах.

Пользователь разрешил только три учебные WhatsApp OGG. Записи и транскрипции не сохранены в Git/логах/отчёте; эталон использовался только для сравнения в памяти, не передавался как подсказка распознавания. Клиент автоматически не выбирался и не создавался.

| RU, 8.01.56 | 3000 / 1000 / 2000 | Все суммы верны, 4.703 с | STT HTTP 200; извлечение дважды достигло общего timeout 25 с, валидированный результат отсутствует |

Долг в таблице — диагностическая разность двух извлечённых сумм, не запись баланса. Для успешных ответов выполнялась проверка `total_minor/received_minor` против 300000/100000, 500000/200000, 700000/400000 соответственно.

Дословного совпадения транскрипций после нормализации регистра, пунктуации и известных числительных не было: mini RU — две группы изменений, KZ — одна, mixed — две; GPT-Transcribe KZ/mixed — по три. Это не WER и не независимая оценка носителем языка. Существенные ошибки mini отражены выше; совпадение денежных полей GPT-Transcribe не означает идеальную транскрипцию. В RU с новой STT моделью точность окончательного результата не оценена из-за timeout извлечения, не из-за доказанной ошибки аудио.

Повтор RU был **один отдельный ограниченный диагностический запуск**. После второго timeout дальнейшие платные повторы остановлены. STT первого RU завершилась HTTP 200 за 1.344 с; оставшийся deadline истёк в Responses/Luna. Это подтверждённый timeout, не HTTP 429 и не доказанная ошибка ключа.

## Поведение реализации и ограничения отмены

- `OpenAIProvider` не имеет доступа к БД/денежным tools. Сервер повторно валидирует JSON/Pydantic, допустимые суммы и цитаты доказательств. Текст транскрипции берётся из STT, а не из переписанного LLM ответа.
- Общий deadline 25 с включает STT + extraction и, если явно включён, fallback. OpenAI pipeline вызывается один раз: текст — один HTTP, аудио — два. Автоматического платного retry нет. Отклоняются неполный ответ, refusal, malformed JSON/envelope и поздний ответ.
- Опциональный `AI_FALLBACK_OPENAI=true` при `AI_PROVIDER=gemini`: максимум один переход на OpenAI после HTTP 503 или transport/primary timeout. Primary по умолчанию 8 с; fallback использует остаток 25 с. Не применяется на 400/401/403/429, ошибки настройки, доступа/membership, валидации/парсинга или отмену. Fallback проверен заглушками и локальной PostgreSQL, но **не включён и не принят в живом сквозном режиме**.
- Membership проверяется до обращения к провайдеру и при сохранении. Клиентский disconnect после чтения тела отслеживается по ASGI `http.disconnect`, включая middleware; задача отменяется, поздний результат отбрасывается, фоновых сохранений нет. Реальный TCP-тест обнаружил и исправил непригодность прежнего `is_disconnected()` probe за middleware.
- Disconnect, пришедший уже во время синхронного COMMIT сохранения, не может гарантированно отозвать начатую транзакцию: возможен недоставленный неиспользованный TTL-черновик. Это не денежная операция. У `POST drafts` по-прежнему нет идемпотентности между **разными** запросами; UI должен игнорировать отменённые/устаревшие ответы. Ни timeout, ни fallback не создают второй результат в рамках одного запроса.
- TTL 30 минут, автор/точка, одноразовое атомарное подтверждение через журнал не изменены. Сбой сохраняет возможность ручного ввода; форма frontend не изменялась.
- Логируются только request_id, этап, provider/model, статус, тип/код ошибки, длительность, токены/длительность аудио и оценка стоимости. Ни текст, ни аудио, ни имя файла, ни ключ/JWT, ни полный ответ/exception message не логируются. `store=false` не означает обещания zero-retention со стороны провайдера.

## Автоматические проверки и рекомендация

**280 backend tests PASS** на отдельной локальной PostgreSQL (полный набор), включая 33 OpenAI/fallback/timeout/disconnect tests; providers в этих тестах — явные заглушки. Реальный loopback TCP + настоящая test PostgreSQL проверили разрыв соединения, поздний ответ и отсутствие Draft/Operation. Auth/membership до вызова, уточнение, один fallback → один Draft/0 Operations, прежние TTL/конкурентное подтверждение/денежные правила покрыты набором. Ruff check/format и `export_contracts --check` выполнены; публичные OpenAPI/generated.ts/примеры не изменились.

Команды из `apps/api`:

```powershell
uv run python scripts/with_env.py .env.local-postgres -m pytest -q
uv run ruff check app tests scripts migrations
uv run ruff format --check app tests scripts migrations
uv run python -m app.export_contracts --check
```

`.env.local-postgres` обязан указывать отдельную пустую `*_test`, отличную от общей БД. Ни очищающих тестов, ни seed, ни writes на общей Supabase в этом этапе не было. Физический микрофон/новая браузерная приёмка/Flutter и общий сервер с OpenAI не проверялись.

Рекомендация: явный OpenAI для ограниченной проверки текстовых черновиков; кандидат для речи — GPT-Transcribe + Luna, **но полный голосовой rollout пока не рекомендован из-за двух RU timeout**. Следующий шаг — review, согласованное отдельное окно и ограниченная HTTP/UI-приёмка; определить причину/стабильность RU Responses timeout до признания речи готовой. Массовые расходы отдельно согласовать. Customer recovery 0006/0.6.2 ждёт сообщения «окно открыто» и свежего backup/restore; этот PR не применяет миграцию и не перезапускает общий сервер.
