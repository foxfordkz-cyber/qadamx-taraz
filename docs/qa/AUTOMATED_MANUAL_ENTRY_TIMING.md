# Automated Playwright Timing — ручная форма

**Классификация: synthetic E2E / Automated Playwright Timing.** Это фактическое время автоматизированных действий Playwright в локальном frontend с подставленными Auth/API. Это не скорость человека, не production latency, не время голосового ввода и не доказательство превосходства AI.

Неудачных попыток в этом прогоне нет. Код сохраняет каждую строку в `finally`, включая elapsed-to-failure и ошибку, и не делает автоматических повторов. При новом запуске создаётся отдельный JSON по UTC run ID; предыдущие результаты не заменяются.

## Методология

1. Используется существующая React-форма, существующие `mockServices`/`login` из `e2e/qa-fixtures.ts`, синтетический пользователь и клиент `QA Клиент A`. Нового runner нет.
2. Вход, открытие `/seller/sale`, переключение языка и ожидание пустой доступной формы происходят до измеряемого интервала, одинаково для всех строк. Они исключены из времени.
3. `process.hrtime.bigint()` фиксируется непосредственно перед первым автоматизированным нажатием «Заполнить вручную» / «Қолмен толтыру».
4. Время включает click/fill/selectOption, выбор существующего клиента, валидацию/уточнение в №5, подтверждение, обработку synthetic API и обновление UI.
5. Перехватчик проверяет локальный origin, business ID, отдельный idempotency key, тип и точное тело операции. Для №4 проверяется `sale_id`, полученный из №1. Затем возвращается типизированный `OperationResponse` с заранее заданными тестовыми значениями.
6. Таймер останавливается после видимого статуса «Запись сохранена сервером» / «Сервер жазбаны сақтады» и проверки ровно одного ожидаемого POST. Один HTTP 201 без верного тела/состояния UI не считается успехом.
7. В №5 получено не заменяется нулём. 700 ₸ — **явное synthetic уточнение**, а не распознанное значение и не данные реальной операции. Распознавание/AI-вопросы этот тест не проверяет.

## Практические пределы

- `fill()` и `selectOption()` не моделируют скорость печати, чтение, поиск клиента человеком или принятие решения.
- Синтетический ответ не содержит реальной сетевой/серверной задержки. Подставленные финансовые снимки не проверяют серверные расчёты, авторизацию БД или exactly-once.
- Использован один общий синтетический клиент fixture; подбор конкретного человека по произнесённому имени не проверяется. Создание клиента в эти интервалы не входит.
- Один прогон на рабочем Windows-компьютере, без контролируемой фоновой нагрузки и benchmark warm-up. Различие строк не интерпретируется как различие языковой производительности.
- Сюда не входят запись/прослушивание/AI/исправления AI-полей. Человеческих парных времён нет, поэтому сравнение и медиана Manual/Voice не рассчитываются, проценты ускорения не публикуются.
