# Как начать работу с GitHub и AI

Для команды из пяти человек храним код, ТЗ и контекст в одном репозитории `foxfordkz-cyber/qadamx-taraz`. Документы лежат распакованными в `docs/team5`; ZIP служит только способом передачи первоначального пакета.

## Что означает каждое действие

| Действие | Простое объяснение |
|---|---|
| clone | Скачать репозиторий с историей в первый раз |
| branch | Отдельная линия работы над задачей |
| commit | Сохранить выбранные изменения в локальной истории |
| push | Отправить свои commits на GitHub |
| pull | Получить и объединить изменения выбранной удалённой ветки |
| pull request или PR | Предложить команде проверить и слить изменения ветки |
| merge | Объединить изменения веток |

`git pull` и pull request — разные действия. Изменения соседнего участника попадут в общую версию после слияния его PR в `main`.

## Капитану сначала

1. Опубликовать этот пакет документации отдельным PR и слить его в `main`.
2. В настройках репозитория дать четырём участникам доступ на запись через их собственные GitHub-аккаунты. Для администратора организации путь: Settings → Collaborators & teams → Add people. [Инструкция GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/managing-teams-and-people-with-access-to-your-repository).
3. Назначить каждому роль из README. `main` обновлять через проверенные PR; организатор слияний — капитан.
4. Первые технические задачи: капитан создаёт схемы/API, владелец кабинета создаёт единый frontend-каркас. Остальные не создают конкурирующие React-приложения.

Установка новых прав и отправка приглашений требуют действий администратора репозитория. Сам пакет документов не меняет доступы GitHub.

## Как загрузить подготовленные файлы

Если работаешь с уже подготовленной локальной копией, открой её папку. Для первоначальной загрузки используй ветку `docs/team-context`. Сначала проверь `git status`, текущую ветку и историю, чтобы не повторять уже выполненную публикацию.

Если используешь ZIP на другом компьютере, сначала клонируй репозиторий и создай ветку:

```powershell
git clone https://github.com/foxfordkz-cyber/qadamx-taraz.git
cd qadamx-taraz
git switch -c docs/team-context
```

Распакуй содержимое нового архива в корень этой локальной копии: `AGENTS.md` должен лежать рядом с README и папкой `.git`. Не копируй архив внутрь репозитория вместо файлов. Если репозиторий уже изменился, проверь существующие README/AGENTS/docs перед заменой и объедини нужные части.

Затем:

```powershell
git status
git add README.md AGENTS.md CONTRIBUTING.md .gitignore .gitattributes .github docs
git diff --cached
git commit -m "docs: add team specs and AI context"
git push -u origin docs/team-context
```

После push открой GitHub, создай PR из `docs/team-context` в `main`, проверь изменения и слей. Если Git просит настроить имя/email, укажи свои данные автора; для приватности можно использовать noreply email из своего GitHub-профиля. Если push требует вход, пройди штатную авторизацию Git/GitHub; токены не вставляются в документы или URL репозитория.

## Каждому участнику один раз

После слияния общего пакета и получения доступа:

```powershell
git clone https://github.com/foxfordkz-cyber/qadamx-taraz.git
cd qadamx-taraz
```

Если локальная копия уже есть, повторный clone не нужен. Открой именно эту папку как проект в своём редакторе с AI. Не открывай только отдельный файл ТЗ: агенту нужен доступ к коду и соседним документам.

Прочитай README, выбери свою роль, создай feature-ветку по [CONTRIBUTING](../CONTRIBUTING.md). Для капитана пример — `backend/bootstrap-api`. Скопируй соответствующий запрос из [AI_PROMPTS](AI_PROMPTS.md).

## Как AI получает контекст

`AGENTS.md` задаёт правила и указывает, что читать. `docs/team5` содержит ТЗ. `docs/DECISIONS.md` сохраняет общие решения. `docs/handoffs/<роль>.md` сообщает, что уже выполнено и что продолжать. Реальная готовность проверяется по коду, тестам и текущей ветке.

Codex собирает инструкции AGENTS при запуске. После изменения этих инструкций новая сессия в папке репозитория подхватит их; в продолжающемся чате явно попроси перечитать обновлённые файлы. [Официальная документация AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

У другого AI-редактора механизм автозагрузки может отличаться. Универсальный способ — прямо попросить прочитать `AGENTS.md` и документы своей роли. Файлы должны быть доступны агенту локально или через подключённый репозиторий. Чат без доступа к репозиторию не узнает содержимое от одного упоминания имени файла.

После синхронизации можно отправлять такой запрос:

> Я обновил ветку из main. Перечитай AGENTS.md, docs/PROJECT_STATUS.md, docs/DECISIONS.md и актуальный файл передачи моей роли. Посмотри изменения кода, затрагивающие мою задачу. Назови изменения контракта, если они есть, и продолжай следующий шаг по моему ТЗ. Не полагайся на старую переписку.

История личного чата не передаётся через Git. В общий репозиторий записываются решения и результаты, нужные следующему участнику. Не нужно загружать туда всю переписку или секреты.

## Рабочий цикл

Задача → своя ветка → код → подходящая проверка → обновление файла передачи → commit → push → PR → проверка → merge в main → синхронизация у команды. Начинайте интеграцию в первый день, небольшими готовыми частями. Подробные команды для обновления существующей ветки — в [CONTRIBUTING](../CONTRIBUTING.md).

Готовый файл передачи полезнее сообщения «всё сделал»: он указывает пути, команду запуска, фактические проверки, изменения API и следующий шаг. Обновлять его должен AI вместе с задачей, а человек проверяет точность перед commit.
