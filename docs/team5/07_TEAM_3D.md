# Задание художнику на три торговые площадки

Твой результат — три узнаваемые стилизованные модели MART, Кайкармета и Ауыл Береке, которые быстро открываются в браузере и помогают выбрать площадку. В первую очередь важны силуэт, композиция, цвет и удобная камера. Точный цифровой двойник всего рынка за два дня не требуется.

## Референсы и смысл

Собери по 2–4 референса на площадку: собственное фото с доступного места или открытые фотографии с записанным источником. Если внешний вид не подтверждён, сделать условный павильон с подписью площадки и пометкой «Концептуальная модель». Не выдумывать реальные номера рядов, точек и этажей.

MART — композиция торгового центра с главным входом. Кайкармет и Ауыл Береке — разные композиции торговых рядов/павильонов по проверенным референсам. Различие создают силуэт, цвет, вход и расположение крупных объёмов. Подробность первого выбранного объекта выше; два остальных могут быть проще, но должны быть завершены.

Сцена показывает одну подробную площадку за раз. Географическое расстояние между тремя моделями в обзорной композиции условное. Модель не обещает покупателю точный путь до реального продавца.

## Что передать frontend разработчику №2

```text
models/mart.glb
models/kaikarmet.glb
models/auyl-bereke.glb
previews/mart.webp
previews/kaikarmet.webp
previews/auyl-bereke.webp
venue-assets.json
asset-sources.md
```

Исходные `.blend` сохранить отдельно от web bundle и передать команде. В `asset-sources.md` указать референсы, автора моделей, происхождение текстур и ограничения использования. Для надписей предпочтительны обычные HTML-подписи frontend; текст не должен становиться нечитаемым при уменьшении модели.

## Технический договор

| Параметр | Требование |
|---|---|
| Формат | GLB, встроенные материалы и текстуры, без внешних путей |
| Оси | В экспортированном GLB +Y вверх, главный фасад ориентирован к +Z |
| Масштаб | 1 unit = 1 метр; при условных размерах явно указать conceptual_scale |
| Origin | Центр здания/комплекса на уровне земли; основание при y=0 |
| Трансформации | Apply scale/rotation; положительный масштаб; корректные нормали |
| Геометрия | Цель до 30 000 треугольников на подробную площадку |
| Файл | Цель до 1,5 МБ на GLB, предпросмотр до 200 КБ |
| Текстуры | До 1024 px; предпочтительны простые материалы и цвета |
| Сцена | Без обязательных внешних шейдеров, тяжёлых частиц и вложенных камер, мешающих общей камере |
| Контактные точки | Три простых hotspot на площадку, координаты в локальной системе модели |

Не применять сжатие, которое требует неизвестного frontend декодера. Если бюджет превышен, сначала уменьшить геометрию/текстуры; затем совместно с разработчиком выбрать сжатие и проверить загрузку в приложении.

В `venue-assets.json`: slug площадки, URL модели и картинки, центр, bounding box, camera position/target и массив hotspot. Пример схемы находится в `fixtures/venue-assets.example.json`. Hotspot хранит ID и slug учебной точки; перед финалом разработчик сопоставляет их с seed API. Координаты не переименовываются в географические широту/долготу.

## Контрольные передачи

| Часы | Результат |
|---|---|
| 0–2 | Референсы, общий стиль и один тестовый GLB для проверки масштаба |
| 2–6 | Черновые объёмы всех трёх площадок; frontend уже может загружать файлы |
| 6–10 | Первая законченная площадка, материалы, камера |
| 10–12 | Уточнение двух остальных; до часа на разговор/референсы вместе с №4 |
| 12–16 | Все три финальные модели и согласованные hotspot |
| 16–20 | Оптимизация, webp-превью, manifest, проверка на телефоне |
| 20–22 | Исправления масштаба, света и кликабельности в настоящем приложении |
| 22–24 | Скриншоты для защиты, передача исходников и резерв |

Не ждать финальной детализации для первой передачи: frontend №2 должен увидеть реальный файл в первые два часа.

## Приёмка

Каждая модель открывается в реальном приложении, целиком попадает в начальный кадр, не проваливается под землю и не требует отсутствующих текстур. Hotspot находятся над нужными условными зонами. В запасном режиме видны качественные изображения. У всех трёх моделей единый стиль. Размеры файлов и число треугольников записаны в отчёт; если превышены цели, команда измерила производительность и приняла решение осознанно.
