# Задание frontend разработчику публичной витрины

Твой результат — зрелищный и понятный вход в Qadam: три местные площадки, 3D-выбор, каталог торговых точек и рабочая клиентская заявка. Ты интегрируешь модели художника в браузер; сам художник не обязан писать React.

## Файлы и границы

Владеешь `apps/web/src/features/explore` и `features/inquiry`. Маршруты: `/`, `/venues/:slug`, `/shops/:slug`. Общие компоненты и router предоставляет участник №3. Методы API и типы согласованы в [контракте](02_ARCHITECTURE_API.md). Модели передаёт участник №5 по [3D-заданию](07_TEAM_3D.md).

Не делай второй независимый frontend-проект. Запросы к базе и AI напрямую из браузера не нужны. Все данные точек приходят из API. 3D-анимация влияет на выбор и фокус, но не меняет бизнес-данные.

## Экраны

1. Главная: краткая польза, кнопки «Найти магазин» и «Кабинет продавца», сцена, три доступные с клавиатуры карточки площадок.
2. Площадка: название, явная метка концептуальной схемы, категории, поиск, точки. При выборе hotspot открывается та же точка, что в списке.
3. Точка: категория, описание, учебный каталог, цена либо «Уточнить», форма заявки.
4. Успех отправки: номер заявки и короткое подтверждение. Не обещать время ответа или наличие товара, если их не предоставил продавец.

## Поведение 3D

Первый вариант сцены работает с простыми блоками до получения GLB. Обзор показывает облегчённые силуэты трёх площадок; подробная модель подгружается только при выборе одной. Выделение, hover и плавная камера дополняют HTML-интерфейс. Нужны ограниченный zoom, предотвращение проваливания под землю и кнопка «Общий вид».

Состояния: загрузка, выбранная площадка, выбранная точка, ошибка модели, WebGL недоступен. Во всех состояниях карточки и заявка доступны. При reduced motion камера меняется без длительного перелёта. На мобильном жесты не должны мешать вертикальному скроллу страницы.

Целевые бюджеты совместно с художником: модель одной площадки до 1,5 МБ и 30 тысяч треугольников; текстуры до 1024 px; без тяжёлого bloom и непрерывных теней. Отрисовка по требованию, ограничение pixel ratio на телефоне, освобождение ресурсов при смене сцены. Замерить скорость на одном реальном телефоне; заявлять достигнутые значения, а не проектные цели.

## Интеграция

Используешь `GET /venues`, `GET /businesses`, `GET /businesses/{slug}`, `POST /businesses/{id}/inquiries`. Фильтры хранятся в URL или предсказуемом состоянии. Запрос заявки получает один `client_request_id`, который сохраняется при сетевом повторе.

Контакт обязателен для заявки, но не публикуется. Валидация длины/формата на клиенте дополняет серверную. При ошибке введённый текст остаётся. При загрузке кнопка недоступна для повторного нажатия. После успеха перейти в состояние подтверждения, не очищать форму раньше ответа.

## План на 24 рабочих часа

| Часы | Результат |
|---|---|
| 0–2 | Согласованы компоненты, рабочие маршруты и блоковая сцена |
| 2–6 | Витрина, площадки, карточки, поиск на тестовом адаптере |
| 6–10 | Реальный API и сохранение обращения |
| 10–12 | Первый GLB интегрирован; мобильная версия и fallback |
| 12–17 | Все три модели, камера, выбор, подробные карточки |
| 17–20 | RU/KZ, состояния ошибок, доступность и производительность |
| 20–22 | Общая проверка обращения до кабинета продавца |
| 22–24 | Полировка и запись фрагмента демо |

## Критерии готовности

- MART, Кайкармет и Ауыл Береке выбираются и открывают правильные точки.
- После клика по сцене и по обычной карточке открывается одинаковая сущность.
- Обращение переживает обновление страницы у владельца: оно сохранено сервером.
- Нет персональных долгов, номеров клиентов и внутренних заявок в публичной выдаче.
- На ширине 360 px форма и кнопки видны; отключение WebGL не блокирует основной путь.
- Учебные точки и условная геометрия подписаны.
- В итоговой сборке нет скрытой подмены API случайными числами или моками.

Не расширяй задачу до карты всего Тараза, внутренней навигации по реальному рынку, оплаты заказа и отдельного AI-поиска. Зрелищность достигается законченной сценой, светом, камерой и понятным переходом к действию.
