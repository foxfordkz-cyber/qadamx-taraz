# Qadam Business пакет для команды из пяти человек

Актуальная версия от 15 октября 2026 года. Срок разработки — два дня. Эта версия заменяет прежнее распределение на трёх участников.

Продукт: голосовой помощник продавца с учётом продаж, оплат и долгов, входящими заявками и общей 3D-витриной MART, Кайкармета и Ауыл Береке. Основной сценарий: сказал → проверил → записал → увидел итог дня.

## Что читать

1. Всем — [продукт и границы MVP](00_PRODUCT_TZ.md).
2. Всем разработчикам — [архитектура и контракт API](02_ARCHITECTURE_API.md).
3. Каждому — своё задание из таблицы ниже.
4. Перед началом — [план двух дней, демо и приёмка](08_PLAN_DEMO_QA.md).
5. Для защиты — [исследование рынка Тараза](01_TARAZ_MARKET.md).

| Участник | Ответственность | Индивидуальное ТЗ |
|---|---|---|
| 1 — капитан | Весь backend, БД, AI, доступы, развёртывание API | [Backend](03_TEAM_BACKEND.md) |
| 2 — frontend | Публичная витрина, каталог площадок, клиентская заявка, интеграция 3D | [Публичный frontend](04_TEAM_PUBLIC_FRONTEND.md) |
| 3 — frontend | Общий каркас приложения, авторизация, кабинет, заявки, клиенты, каталог | [Кабинет продавца](05_TEAM_SELLER_FRONTEND.md) |
| 4 — frontend | Голосовой ввод, подтверждение операции, долги, итог дня, проверка демо | [Учёт и AI-интерфейс](06_TEAM_LEDGER_FRONTEND.md) |
| 5 — 3D | Три модели площадок, изображения для запасного режима, параметры сцены | [3D-модели](07_TEAM_3D.md) |

В папке `fixtures` находятся учебные сценарии AI и пример договора передачи 3D-ассетов. Это входные данные для разработки и тестов, а не результаты уже проведённых испытаний.

В первые два часа капитан публикует схемы API и ответы-примеры; frontend №3 собирает единый каркас; frontend №2 показывает сцену из простых блоков; frontend №4 делает форму ручной продажи; 3D-художник передаёт первый пробный GLB. На шестом рабочем часу должна сохраняться настоящая операция в БД.

Подтверждённых подключений MART и рынков пока нет. Названия площадок отражают выбранный местный контекст; торговые точки, операции и внутреннее размещение в демо — учебные. Участники команды не должны представлять их действующими клиентами проекта.
