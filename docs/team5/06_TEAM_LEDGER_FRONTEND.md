# Задание frontend разработчику голосового учёта

Твой результат — главный сценарий защиты: продавец произносит фразу, проверяет понятный черновик, подтверждает и видит изменение долга и итогов. Ты делаешь интерфейс и проверку сценария; вся обработка AI и запись денег остаются на backend капитана.

## Файлы и границы

Владеешь `features/voice`, `features/ledger`, `features/summary`. Маршруты: `/seller/sale`, `/seller/debts`, `/seller/history`, `/seller/summary`. Каркас, auth, клиенты и общие компоненты предоставляет участник №3. Контракт сумм и методов — в [архитектуре](02_ARCHITECTURE_API.md).

## Голосовой ввод

Один экран с двумя равноправными входами: «Сказать голосом» и «Ввести вручную». Запись начинается только после действия пользователя. Есть таймер до 30 секунд, остановка, отмена, воспроизведение и отправка. При запрете микрофона доступны текст и загрузка аудиофайла. Перед записью коротко сообщается, что аудио будет обработано AI.

Проверяй поддержку MIME в MediaRecorder и согласуй формат с капитаном. HTTPS обязателен для нормальной работы микрофона вне localhost. Не использовать браузерный speech recognition как единственный способ: поддержка и языки могут отличаться.

Состояния интерфейса: `idle → recording → ready → parsing → review → saving → saved`, отдельно `error`. После AI-ошибки остаётся возможность ручной записи; пользователь не теряет введённый текст. Во время сохранения повторное нажатие блокируется.

## Карточка подтверждения

Показывать расшифровку и редактируемые поля: тип операции, описание, клиент, сумма продажи, полученная сумма; для погашения — выбранная продажа и сумма оплаты. Разницу показывать как «Осталось оплатить», но конечный результат всегда подтверждает backend.

Если не ясно, оплачена ли продажа, не подставлять автоматически полную оплату. Если несколько Асқаров или несколько открытых продаж — дать явный выбор. При долге нельзя подтвердить без клиента. Создание клиента выполняется через общий компонент участника №3.

Кнопка подтверждения называет действие: «Записать продажу 3 000 ₸» либо «Записать оплату 500 ₸». До нажатия в истории нет новой операции. При изменении суммы пользователь видит итог перед отправкой.

Для одного сохранения создать `Idempotency-Key`. При timeout и повторе того же запроса использовать тот же ключ и тело. При новой операции — новый ключ. Не очищать черновик до подтверждённого ответа сервера. Если результат неизвестен из-за сети, показать «Проверяем сохранение», а не «Не сохранено» без проверки.

## Долги и итог дня

Долги: список клиентов и неоплаченных продаж, поиск, сумма остатка, действие «Получена оплата». Нельзя делать публичный рейтинг должников или оценку кредитоспособности. Ввод погашения ограничивается текущим остатком; при серверном конфликте список обновляется.

История: хронология, тип операции, суммы, краткое описание, пометка отмены. Действие «Отменить ошибочную запись» объясняет последствия и требует подтверждения. Если у продажи есть действующие погашения, показать понятный ответ backend и предложить открыть связанные записи.

Итог дня: «Продано за день», «Получено за день», «Мне должны сейчас», «Новых заявок». Последний денежный показатель относится ко всей истории. Не переименовывать поступления в прибыль. Не рисовать график из придуманных данных, если временной ряд не предоставлен API.

После успешной операции обновить историю, клиентов, открытые продажи и summary через инвалидирование запросов. Ошибка API не должна менять карточки так, будто деньги уже записаны.

## Проверка языка и полезности

Ты собираешь 20 коротких фраз: 8 RU, 8 KZ, 4 смешанных; минимум 6 должны требовать уточнения. Начальные шаблоны находятся в `fixtures/ai_cases.json`. Участник команды, уверенно владеющий казахским, проверяет формулировки и переводы. Запиши реальные аудио, включая несколько с фоновым шумом, с согласия говорящего.

Вместе с участником №5 найди 2–3 продавцов для короткого разговора, если это доступно. На это выделен один рабочий час, а не весь день. Капитану передай конкретный процесс и одну приоритетную поправку. Если контактов нет, проведи пользовательский тест и честно подпиши его как тест на учебных данных.

## План на 24 рабочих часа

| Часы | Результат |
|---|---|
| 0–2 | Ручная форма и карточка подтверждения на контрактных примерах |
| 2–5 | Микрофон, файл, текст и состояния ожидания |
| 5–8 | Реальная запись продажи и обновление итогов |
| 8–11 | Долги, выбор продажи, погашение, история |
| 11–12 | Интервью либо подготовка пользовательского теста |
| 12–16 | AI-черновик, неоднозначности, ошибки, отмена |
| 16–19 | Языковые прогоны и проверка денег с капитаном |
| 19–22 | Проверка телефона, времени операций, общий end-to-end |
| 22–24 | Запись демо и таблица фактических результатов |

## Приёмка

На живом API повторить последовательность 3 000 / 1 000 / 500: продажи 3 000, поступления 1 500, долг 1 500. Проверить двойное нажатие, timeout, отсутствие микрофона, неверный JSON AI, двух одноимённых клиентов, два долга одного клиента, переплату и обновление страницы. После каждого сбоя пользователь понимает, сохранилась ли операция и что делать дальше.
