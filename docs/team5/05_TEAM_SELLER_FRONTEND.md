# Задание frontend разработчику кабинета продавца

Твой результат — единое web-приложение, в котором продавец входит, видит свои заявки, клиентов и каталог. Ты владеешь общим каркасом и дизайн-системой, чтобы три frontend-части выглядели одним продуктом.

## Файлы и границы

Владеешь `apps/web/src/app`, `shared/ui`, базовой i18n-конфигурацией, общим API-клиентом и `features/seller`. Маршруты: `/login`, `/seller`, `/seller/inquiries`, `/seller/customers`, `/seller/catalog`. Денежные формы и расчётные карточки делает участник №4; публичную витрину — №2.

Корневые зависимости, router, QueryClient, AuthProvider и общая тема меняются через тебя. Backend и схемы задаёт капитан. Сгенерируй TypeScript-типы из его OpenAPI либо синхронизируй первые интерфейсы по его точным примерам до генерации. Не создавай собственную альтернативную форму данных.

## Каркас в первые два часа

Создай одно React/TypeScript/Vite приложение, базовые маршруты и общий layout. Выдай другим участникам готовые Button, Input, Card, Dialog, Alert, Spinner, EmptyState, форматтер KZT и API-клиент. Договорись об export страниц и параметрах текущей точки.

Дизайн-токены: фон `#F7F3EB`, основной текст `#172A27`, фирменный акцент `#B32918`, спокойная зелёная подложка `#D9EEDB`. Оттенки ошибок и успеха проверяются на контраст. Шрифт с поддержкой русских и казахских букв; не терять Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І. Все цифры сумм используют единый формат.

## Функции

Вход через Supabase Auth. После входа `GET /me` определяет разрешённые точки. Выбор точки берётся из этого списка; случайный ID в URL не даёт новых прав. После выхода Query cache очищается, чтобы следующий пользователь не видел данные предыдущего.

Кабинет содержит простую навигацию: «Продажа», «Мне должны», «Заявки», «Итог дня». Дополнительные разделы «Клиенты», «Каталог», «История» доступны без перегрузки главного экрана. Выбранная точка видна рядом с названием кабинета.

Заявки: список по новизне, три статуса, карточка с сообщением и контактом. При изменении статуса показать сохранение и ошибку. Нельзя незаметно помечать запрос проданным или оплаченным. Обновлять список при возврате на вкладку; периодический опрос допустим раз в 10–15 секунд только на активной странице.

Клиенты: поиск, имя и различающая заметка, создание клиента, переход к его долгам в экран участника №4. Одинаковые имена допустимы; не объединять клиентов автоматически. Контакт необязателен; нельзя требовать телефон для каждой наличной продажи.

Каталог: список учебных товаров из API, цена либо отсутствие цены, доступность. Формы редактирования включать только после готовности серверных методов. До этого не рисовать «Сохранено», когда изменение осталось лишь в браузере.

## Интеграция с соседними экранами

Участнику №4 передай `businessId`, доступ к auth-aware API-клиенту, хук поиска клиентов, действие создания клиента и общие поля ввода. Он передаёт тебе страницы продажи, долгов, истории и summary. Участник №2 передаёт публичные страницы и сцену. Ты подключаешь их в router без копирования бизнес-логики.

Тексты модулей авторы передают отдельными RU/KZ-словарями. Ты следишь за едиными словами: «Получено», «Осталось оплатить», «Мне должны сейчас», «Заявка». Не использовать технические названия вроде ledger, tenant, pipeline в интерфейсе продавца.

## План на 24 рабочих часа

| Часы | Результат |
|---|---|
| 0–2 | Каркас и базовые компоненты переданы коллегам |
| 2–5 | Auth, выбор точки, защищённые страницы, API-клиент |
| 5–9 | Заявки и статусы на живом API |
| 9–12 | Клиенты, поиск, каталог, UI ошибок |
| 12–16 | Общая сборка трёх frontend-модулей |
| 16–19 | RU/KZ, мобильная версия, единый визуальный стиль |
| 19–21 | Публикация web и проверка переменных/CORS с капитаном |
| 21–24 | Исправления интеграции и финальная репетиция |

## Критерии готовности

После входа видна только разрешённая точка; смена пользователя очищает данные предыдущего. Входящая заявка из публичной витрины появляется у правильного продавца. Обновление страницы сохраняет статус. Клиента можно создать и выбрать в денежной форме. Общие компоненты одинаковы во всех экранах. Нет секретных API-ключей в web bundle. На телефоне навигация и основные действия доступны одной рукой.

В финале передай рабочую web-ссылку, команды сборки, список обязательных публичных env-переменных и список проверенных экранов. Не перекладывай сборку общего frontend на капитана: его критическая работа — backend.
