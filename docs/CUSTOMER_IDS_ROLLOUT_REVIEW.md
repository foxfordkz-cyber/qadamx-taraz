Блокирующих дефектов PR61 не найдено. Проверены:

  выборкой клиентов. Обе SQL-части ограничены business_id; набор ids не позволяет

  фильтра по периоду нет. Новые приватные поля не добавлены.
- До100 входных UUID до дедупликации; первый порядок, полный результат, без
  default limit50; отсутствующие/чужие одинаково исключены, next_cursor=null.
- Пустой/невалидный ids и несовместимые q/cursor/limit дают422. Без ids прежние
  поиск, limit, cursor и форма Page сохранены. SQL параметризован.
- Generated-типы соответствуют OpenAPI. Миграций/env/dependency changes нет.

[Полный контракт, JSON и сериализация](../packages/contracts/CUSTOMER_IDS_API.md).
Ограничение: `ids[]` — неподдерживаемое неизвестное имя; оно не включает ids-режим.
Использовать строго `URLSearchParams.append("ids", uuid)`, а не CSV/JSON/скобки.

## Откат с учётом зависимости

- **Уточнение после проверки Render docs:** кнопка Rollback переиспользует env
  старого deployment. Чтобы сохранить текущие ключи и Preview43 CORS, использовать
  новый **Deploy a specific commit** предыдущего Live SHA с текущими Environment,
  а не слепой Rollback. [Точные действия для окна](CUSTOMER_IDS_RENDER_WINDOW.md).
- **До выпуска frontend:** при сбое API заново развернуть зафиксированный прежний
  Live SHA (последний известный код e699158; либо1a541ef с идентичным apps/api)
  с текущими ключами/env/CORS. БД не откатывать: схема/данные не менялись.
  Проверить health, /me, прежний customers и изоляцию A/B; frontend оставить прежним.
- **После выпуска frontend:** предпочтительно вернуть прежний Vercel deployment,
  сохранив совместимый ids-backend. Старые вкладки/кэш уже могут продолжать ids-запросы;
  один web-rollback не гарантирует их исчезновение.
- Не возвращать обычный backend без ids, пока такие клиенты существуют: он ответит200
  первой страницей вместо нужного набора. При обязательном backend rollback нужен
  отдельно проверенный совместимый патч (сохранение ids или явный отказ ids-запросов
  без раскрытия списка). Такой защитный backend в этом PR не создан и не развёрнут.
- Memberships, денежные операции, AI/env, Auth/Storage и миграции в откат не включать.
