## Результат

- Шесть отдельных карточек: продажи, поступления, количество продаж, средний чек,
  текущий общий долг и количество должников. Первые четыре подписаны «За выбранный
  период», последние две — «Сейчас · все даты».
- Краткая сводка подставляет значения `cards` из подтверждённого ответа API.
  Нет AI, прогнозов, сравнения периодов, прибыли или пересчёта серверных агрегатов.
  Отрицательные поступления сохраняют знак и объяснение возвратов при отменах.
- Выбранные день/час и точные значения находятся над графиком; максимум/отрицательный
  минимум подписаны. На дневном графике есть месяц, на часовом — `HH:00` и количество
  продаж. Часы означают регистрацию действующих продаж за весь выбранный период.
  Столбцы доступны с клавиатуры, по касанию и через сохранённые таблицы.
- Переходы ведут в `/seller/history` и `/seller/debts` без query-параметров и обещаний
  фильтрации. Нулевые продажи/чистые поступления объяснены для выбранного периода,
  при этом прежний долг остаётся видимым. Кнопка «Новая продажа» ведёт в `/seller/sale`.
- Ошибка API скрывает карточки, сводку и пустое состояние. Повтор остаётся ручным;
  ошибка не включает Demo и не превращается в нулевой отчёт.
- Сохранены 7/30 дней, RU/KZ, `null` среднего чека, signed receipts, общий формат KZT,
  Qadam Card/Button/EmptyState, дизайн-токены и изоляция точек/аккаунтов. Для KZ задан
  явный словарь месяцев: установленный Chromium иначе показывал `M10` вместо «қазан».
  Время снимка отображается числовой датой в часовой зоне API. Текстовое отсутствие
  среднего чека помещается в мобильную карточку без разрыва слова.

## Контракт и backend-зависимости

Используется только существующий `GET /api/v1/businesses/{id}/analytics?days=7|30`
через общий клиент и существующие query/validation guards. Источники:
[контракт](../packages/contracts/ANALYTICS_API.md) и checked-in OpenAPI 0.6.2.
Все необходимые поля присутствуют; **новых backend-зависимостей нет**.

Выбор точки и разрешения остаются у существующего `BusinessProvider` и `/me`.
При обычных переходах выбранная точка сохраняется. После полного reload существующий
provider выбирает первую разрешённую точку: выбор хранится только в памяти. Проверка
сверяет отчёт с видимой точкой после reload; сохранение выбора в storage не добавлялось.
