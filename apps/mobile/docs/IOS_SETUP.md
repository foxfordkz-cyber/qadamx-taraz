# iPhone: сборка и приёмка Мал базара

**Подготовлен iOS-проект, а не установочный IPA.** У команды есть iPhone, Mac
пока нет. Подготовка и Dart/widget-проверки выполнены на Windows. Xcode,
подпись, Simulator и физический iPhone здесь не запускались. PR #15 остаётся Draft.

## Что подготовлено

- `ios/Runner.xcworkspace`, Xcode project, Swift AppDelegate/SceneDelegate,
  Flutter 3.47.7 templates, Swift Package Manager и CocoaPods fallback.
- Целевая платформа — **iPhone, iOS 15.0+**; bundle ID `kz.qadam.qadamMobile`.
  Версия приложения берётся из pubspec: 0.1.1+2. iPad отдельно не заявляется.
- Camera/Photo Library usage descriptions на RU/KZ. Микрофон, геолокация,
  background fetch и разрешение записи в фотобиблиотеку не запрашиваются.
  Системный язык разрешений определяется iOS, язык интерфейса — переключателем.
- Supabase SDK сохраняет сессию в iOS Keychain; сессия, черновики и ключи
  pending доступны на разблокированном устройстве и не мигрируют на другое.
  iCloud synchronization не включён; entitlement ограничен этим приложением.
- Фото идут в существующий FastAPI, не в Storage напрямую. Не запрашиваются
  полные метаданные фотобиблиотеки. Проверяется размер полученного файла до
  8 MiB; image_picker на iOS может преобразовать исходный HEIC в JPEG.
- После прерывания picker на iOS восстанавливается форма и предлагается
  повторный выбор; Android-only retrieveLostData не вызывается.
- `tool/build_ios.dart` допускает только три публичных поля и HTTPS API.
  Значения не печатает. На Windows отказывает в сборке с понятной причиной.

## Когда появится Mac

1. Установить Flutter **3.47.7 stable**, совместимый Xcode с iOS SDK и CocoaPods
   для зависимостей без SwiftPM. Выполнить `flutter doctor -v`, исправить
   замечания iOS toolchain. Настройка Xcode и принятие его лицензии — на Mac.
   [Официальная инструкция Flutter](https://docs.flutter.dev/platform-integration/ios/setup).
2. Получить ветку `feature/mobile-livestock-api`, перейти в `apps/mobile`.
   Не запускать повторный `flutter create`: iOS-проект уже подготовлен.
3. Получить текущий HTTPS API_BASE_URL и публичный конфиг капитана. Старый
   Quick Tunnel может прекратить работу. Скопировать `config/public.example.json`
   в игнорируемый `config/public.local.json`, заполнить **только** API_BASE_URL,
   SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY. Supabase-проект тот же:
   `https://pdjjdqgoitnkpgkbqjtp.supabase.co`. Пароли туда не входят.
4. Из `apps/mobile`:

```sh
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
dart run tool/build_ios.dart config/public.local.json validate
dart run tool/build_ios.dart config/public.local.json prepare
open ios/Runner.xcworkspace
```

`prepare` создаёт локальные build settings с публичным конфигом; не собирает
и не подписывает IPA. Нельзя выдавать его успешное выполнение за native build.
Generated.xcconfig и generated plugins не коммитятся.

5. В Xcode: Runner → Signing & Capabilities → выбрать свою Team и Automatic
   Signing. Не добавлять чужие сертификаты/пароли в репозиторий. Альтернатива:
   скопировать `ios/Flutter/Signing.example.xcconfig` в игнорируемый
   `Signing.local.xcconfig` и указать Team ID. Если bundle ID недоступен вашей
   Team, согласовать уникальный ID и изменить его в локальном Runner target
   через Xcode (настройка target имеет приоритет над xcconfig). Пароли Apple ID,
   сертификаты и provisioning profiles в конфиг приложения не входят.
6. Подключить iPhone, доверить Mac, включить Developer Mode, если требуется iOS.
   Получить device ID из `flutter devices`. После настройки подписи:

```sh
dart run tool/build_ios.dart config/public.local.json run IPHONE_DEVICE_ID
```

`run` использует release-режим, чтобы установленное приложение можно было
запускать самостоятельно без подключённого Dart debugger. Это прямая локальная
установка, не TestFlight и не App Store. Для личной проверки поддерживается
бесплатная Personal Team с ограничениями Apple; платные услуги автоматически
не подключаются. [Установка на устройство](https://docs.flutter.dev/platform-integration/ios/setup).

## Другие режимы сборки

```sh
# Только Mac: .app для симулятора, не устанавливается на физический iPhone.
dart run tool/build_ios.dart config/public.local.json simulator

# Только Mac: компиляция для iPhone без подписи, не установочный файл.
dart run tool/build_ios.dart config/public.local.json device
```

Без подписи `.app` нельзя переименовать в `.ipa` и считать готовой к установке.
Подписанный IPA/способ распространения согласуются после появления Mac и Team.
App Store/TestFlight, облачная сборка и платные подписки в этой задаче не настроены.

## Физическая проверка iPhone (15–20 минут)

Использовать учебные A/B и только явно учебные объявления. Пароли получить
закрытым каналом, вводить в форме; не записывать их/токены на видео или в отчёт.

| Шаг | Ожидаемый результат |
|---|---|
| Открыть health в Safari с iPhone, затем ленту приложения без входа | Доступен действующий API; сегодняшние записи/фото, пустые фильтры и ошибки сети показываются честно |
| Войти A, закрыть приложение, открыть и затем перезагрузить/разблокировать iPhone | Сессия восстанавливается; после выхода снова нужен вход. Refresh отдельно отметить только при фактическом обновлении SDK-сессии |
| Камера → фото; затем галерея/выбор ограниченного набора фото | Фото показываются; выбор не требует доступа ко всей библиотеке. Проверить обычный снимок и HEIC с физического iPhone: сервер принимает результат или показывает ошибку без потери формы |
| Отказать камере, отменить picker, свернуть/закрыть приложение во время выбора | Нет падения; поля формы сохраняются, повторный выбор доступен. После выхода A нельзя прикрепить фото A к B |
| Форма → предпросмотр → явное «Опубликовать» | До публикации объявления нет; после подтверждения сервера одна запись с фото в «Моих» и public. Цена за голову, деньги int |
| Авиарежим при отправке → вернуть сеть → повторить | Нет преждевременного успеха, форма сохранена, повтор без дубля с прежним ключом/телом. Потерю именно успешного ответа не считать проверенной обычным авиарежимом |
| Редактирование → «Есть сегодня» → фильтр рынка | Та же запись обновлена; рынок фильтруется вместе с locality; дата берётся с сервера |
| Статистика отдельного учебного рынка | Count=0, minimum=null → «Нет данных», медиана недоступна; учебные цены не выдаются за рынок |
| Выйти A → войти B | «Мои»/черновики/pending A не видны B. Проверка серверного отказа чужому PUT/action выполняется отдельно через HTTP, отсутствие кнопки её не заменяет |
| Снова A → «Продано» | Public запись/фото исчезают; sold остаётся в «Моих», собственное фото открывается; confirm_today не возвращает sold |
| Отдельное тестовое объявление → «Снять» | Withdrawn исчезает из public и остаётся владельцу |
| RU/KZ, маленький iPhone, крупный шрифт, клавиатура, поворот, жест назад | Действия доступны, поля/кнопки не перекрыты, ввод не теряется; нет утечки приватного экрана после выхода |

Ключи Keychain могут пережить удаление приложения. Не использовать переустановку
как способ сбросить неизвестный результат публикации: сначала разрешить pending
под исходным аккаунтом. Удалённый encrypted photo snapshot нельзя восстановить
из Keychain; повтор загрузки тогда требует разбирательства результата с командой.

В отчёте отдельно записать: iPhone/версию iOS, Xcode/Flutter, commit приложения,
API URL/version и подтверждённый commit процесса backend, дату, PASS/FAIL/BLOCKED
по шагам. HTTP с компьютера и widget tests не являются проверкой iPhone.
Видео 60–90 секунд снять после входа: фото/предпросмотр/публикация/мои/сегодня/
рынок/продано. **Фактическая смена суток не проверена**; часы общей БД не менять.
