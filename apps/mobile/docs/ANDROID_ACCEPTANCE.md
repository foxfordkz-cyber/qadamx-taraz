# Мал базар в Qadam 0.2.1: физическая приёмка

Статус: **сценарий подготовлен, на телефоне не выполнен**. PR #15 и #25 остаются Draft
до приёмки. План: 15–20 минут; фактическая смена суток — отдельная проверка.

## Подготовка

- Android 7.0+; записать модель телефона, версию Android, дату/часовой пояс и сеть.
- Установить [qadam-0.2.1-4cc2f52-debug.apk](https://github.com/foxfordkz-cyber/qadamx-taraz/releases/download/mobile-v0.2.1-shell.1/qadam-0.2.1-4cc2f52-debug.apk), версия 0.2.1+4,
  commit приложения `4cc2f528f3e6cd45960b6c3be111a537c66d7e82`.
- SHA256: `3b94829b6618eebc6aff56fd7cd2166b003ede7ef926677821e9bc061335f993`.
- Старые APK 0.1.1/0.2.0 содержат прежние временные URL. Этот сценарий выполняется
  внутри раздела «Мал базар» единой оболочки; оболочку проверить отдельно по
  [QADAM_SHELL_ACCEPTANCE.md](QADAM_SHELL_ACCEPTANCE.md).
- Проверить с телефона health по действующему API_BASE_URL. При недоступности
  туннеля зафиксировать блокер; не включать mock и не использовать localhost.
- Учебные A/B: `owner-a@example.test`, `owner-b@example.test`. Пароли получить
  закрытым каналом и ввести в приложении; не снимать ввод на видео.
- Подготовить безличную тестовую картинку JPEG/PNG/WebP до 8 MiB. Для камеры
  снять лист с надписью «Учебное фото», без людей и личных данных.
- Названия места и рынка должны явно обозначать тест: «Учебная проверка mobile»
  и «Учебный рынок mobile <дата-время>». Контакт: «Учебный тест, связи нет».
  Овца, 2 головы, **30 000 ₸ за голову** (3 000 000 тиын), без реальных предложений.
  Backend должен быть в согласованном demo_mode=true; приложение is_demo не задаёт.

## Шаги и ожидаемые результаты

| № | Действие на физическом Android | Ожидаемый результат |
|---|---|---|
| 1 | Без входа открыть ленту, применить вид/место/рынок, открыть карточку и фото. Затем указать другой рынок. | Загружаются сегодняшние записи API; учебные помечены. Чужой рынок даёт пустой список, не старые записи. Фото видно; private-действия требуют входа. Пустая лента допустима после смены серверных суток. |
| 2 | Войти как A. Закрыть приложение, открыть снова. | Открываются «Мои», сессия восстановлена без повторного ввода; нет ошибок или токенов в сообщениях. Автоматический refresh отдельно отмечать только если реально дождались обновления сессии. |
| 3 | Создать форму: сделать фото камерой и добавить второе из галереи; заполнить тестовые данные и согласие. Открыть предпросмотр, вернуться в форму. | Фото и все поля сохранены; цена за голову, отдельные место/рынок. До нажатия «Опубликовать» объявления нет в публичной ленте. |
| 4 | Включить авиарежим, нажать «Опубликовать». Вернуть сеть и повторить исходное действие. | При ошибке нет сообщения об успехе; форма/фото сохранены. После ответа сервера — одна запись в «Моих» и публичной ленте, без дубля. Это проверка офлайн-повтора; потерю именно успешного ответа отмечать отдельно, если её не воспроизводили. |
| 5 | Открыть свою запись, отредактировать описание и цену на 31 000 ₸, подтвердить сохранение. Нажать «Есть сегодня» дважды как два самостоятельных действия. | Поля обновлены в той же записи; ID/число объявлений не меняются. Дата подтверждения определяется сервером. Новое самостоятельное действие получает новый ключ; сетевой retry сохраняет прежний. |
| 6 | Открыть фильтр этого вида/места/рынка и статистику. | Учебная запись находится в ленте, но исключена из рыночной статистики. Для отдельного учебного рынка count=0, minimum=null → «Нет данных», медиана недоступна; вид/место/рынок/период указаны. Не подменять null нулём или ценой тестового объявления. |
| 7 | Выйти из A, войти в B. Проверить «Мои», открыть публичную запись A. | Записи, черновики и pending A не появляются в «Моих» B; чужую запись нельзя редактировать/продавать через UI. Публичное фото активной сегодняшней записи A доступно B — это правильно. Само отсутствие кнопки не доказывает серверную защиту: HTTP-проверка ниже обязательна отдельно. |
| 8 | Выйти из B, снова войти A. Пометить тестовую запись «Продано», обновить публичную ленту, затем «Мои»/фильтр «Продано». | Запись исчезла из public, остаётся у A как sold; своё фото доступно. «Есть сегодня» недоступно и не возвращает sold в ленту. В денежном журнале продажа не создаётся. |
| 9 | Создать второе явно учебное объявление, затем «Снять объявление». | Исчезает из public, остаётся у A как withdrawn; не появляется у B. Обе тестовые записи завершены, чужие данные не меняются. |
| 10 | Переключить RU/KZ, открыть форму с клавиатурой на маленьком экране/с крупным шрифтом. Отказать камере в разрешении там, где Android запрашивает его. | Подписи переведены, поля/кнопки доступны прокруткой, нет обрезания критических действий. При отказе/отмене камеры форма сохраняется, приложение не падает; галерея остаётся альтернативой. Если системная камера не запросила разрешение, это не считать проверкой отказа. |
| 11 | Выйти, перезапустить приложение, открыть «Мои». | Снова нужен вход; приватные фото/черновики прежнего аккаунта не показаны. |

Положительный минимум на живых **non-demo** данных проверять только в отдельной
согласованной среде либо на существующих подтверждённых предложениях. При count=1–4
показывается серверный минимум, медиана — «Недостаточно данных»; при count>=5 —
оба показателя. Не создавать ложные рыночные объявления и не переключать режим
общего backend ради этой проверки.

## Отдельная проверка с компьютера

Прогон 16 октября 19:25–19:28 UTC+5 выполнен: [результаты](LIVE_HTTP_ACCEPTANCE_021.md).
Ниже сохранён сценарий воспроизведения на 0.6.1. Пауза обновления снята: API 0.6.2,
URL прежний. По указанию пользователя полный HTTP-прогон не повторяется; приоритет —
установка APK и физические шаги выше. Результат 0.6.1 не считается приёмкой 0.6.2.
Это HTTP-приёмка API, **не результат запуска APK**. Обычные Supabase-сессии A/B,
только публичный конфиг; ни service_role, ни прямой Storage не нужны. Пароли и
access/refresh tokens не записывать в stdout, отчёт, shell history или Git.

1. Войти A/B, получить разные JWT subjects. Не подставлять owner_id в body.
2. A: `POST /livestock/photos`, multipart `file`; сохранить ID. Повторить исходные
   байты/URL/Idempotency-Key → тот же ID. Приватное фото: A=200, B=404, anonymous=401.
3. A: `POST /livestock/listings` с photo_ids и учебным рынком; повторить точные
   URL/JSON/key → тот же listing ID, одна запись в mine/public.
4. B: `PUT /livestock/listings/{A_id}` и `POST .../{A_id}/actions` → 404,
   состояние A не изменено. Эти отказанные запросы также имеют собственные ключи.
5. A: редактирование и `confirm_today` → 200; public/mine фильтруются по
   species+locality+market. Чужой рынок пуст. Статистика demo: count=0/minimum=null.
6. A: `sell` → sold; public карточка/фото=404, mine всё ещё содержит запись,
   private photo A=200/B=404. Новый `confirm_today` для sold → 409 INVALID_STATE.
7. Отдельную тестовую запись снять через `withdraw`. Завершить сессии A/B.

Все мутации сначала сохраняют account-bound намерение с URL/body/key. При
неизвестном исходе остановиться и повторить его без изменений под тем же аккаунтом;
новое намерение/ключ не создавать. Не повторять pending A после входа B. Сохранять
в отчёте только статусы, ID тестовых записей, время, commit и PASS/FAIL/BLOCKED.

## Видео и запись результата

60–90 секунд после входа: лента/фильтр → фото/предпросмотр → явная публикация →
«Мои» → «Есть сегодня» → рынок/«Нет данных» → «Продано» → отсутствие в public и
наличие в «Моих». Вход, пароли, уведомления и другие личные данные не снимать.
Это короткое видео основного сценария; остальные пункты отметить в протоколе.

В протоколе: устройство/Android, APK version+commit+SHA256, API URL/version,
подтверждённый commit процесса backend (или «не подтверждён»), время, номер шага,
PASS/FAIL/BLOCKED, наблюдение и ID тестовой записи. Результаты компьютера и Android
вести раздельно. Ни один шаг выше пока не отмечен PASS на устройстве.

**Фактическая смена суток: не проверена.** Для её проверки оставить отдельную
active учебную запись, дождаться реальной полуночи Asia/Almaty: public исчезает,
mine показывает available_today=false; новый confirm_today возвращает active
запись. Часы общей БД не менять. Если не дождались — оставить «не проверена».
