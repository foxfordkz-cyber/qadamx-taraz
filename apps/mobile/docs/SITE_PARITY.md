## Границы реализации

- Продолжать текущую CRM и secure pending; API/customer recovery/финансы не заменять.
- Основные публичные маршруты реализовать Flutter. WebView допустим только для
  локального GLB-renderer с принятыми моделями/manifest; без Auth/API/кабинета,
  внешних переходов и стороннего удалённого JS. Нативные poster/list обязательны.
- Заявки: client_request_id + исходное тело; initial definitive4xx допускает
  исправление, unknown→4xx не снимает блокировку. Клиентский lookup для public
  inquiry отсутствует: не придумывать маршрут. Контакт — свободный текст,
  trim и лимиты100/200/2000 Unicode code points.
- [Запрос владельцу Auth](https://github.com/foxfordkz-cyber/qadamx-taraz/pull/43#issuecomment-6233319221)
  о mobile callback/allowlist/reset отправлен. Подтверждения пока нет; URL не назначен,
  Supabase не меняется, A/B заново не регистрируются.
- Фотографии/контакты/редактирование товаров и клиентов не имитировать.
- Новый APK, его точный SHA и итоговая матрица добавляются после реализации/сборки;
  новые исходники сами по себе не входят в опубликованный0.3.1.
