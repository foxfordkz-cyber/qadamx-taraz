## Этап 2 — native ledger

Главная из `/summary`; клиенты с recovery, ручная продажа/доплата через `/operations`,
долги и пагинированная история. Неизвестное намерение сохранять до запроса в защищённом
хранилище по API/account/business/action. Повтор — тот же URL/key/body. Поздний ответ
не удаляет другой intent: compare-and-clear, проверка identity/epoch перед UI.
`not_observed` не разрешает новый ключ. После успеха обновлять серверные показатели.

## Этап 3 — native AI/analytics

Редактируемый AI-черновик, текст/запись/прослушивание/отмена; анализ только отдельной
кнопкой. Никаких прямых провайдерских ключей и автоматических paid retries.
Аналитика только серверная, 7/30, signed receipts, average=null → «Нет данных».
Браузерный путь сохранить до физической приёмки. При смене аккаунта/точки старые
формы/ответы скрываются; старые pending сохраняются только для своего scope.
