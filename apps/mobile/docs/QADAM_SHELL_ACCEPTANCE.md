## Первый проход на Android после обновления API

Использовать [APK 0.2.1+4](https://github.com/foxfordkz-cyber/qadamx-taraz/releases/download/mobile-v0.2.1-shell.1/qadam-0.2.1-4cc2f52-debug.apk),
source `4cc2f528f3e6cd45960b6c3be111a537c66d7e82`, SHA256
`3b94829b6618eebc6aff56fd7cd2166b003ede7ef926677821e9bc061335f993`.
Адреса и mobile-контракт не изменились; новая сборка для 0.6.2 не нужна.
Заполнить модель/ОС/сеть/время и PASS/FAIL по факту, не по предыдущему HTTP-отчёту.

1. Установить APK (при USB: `adb install -r qadam-0.2.1-4cc2f52-debug.apk`).
   Не очищать данные прежней установки ради обхода pending; проверить запуск ленты.
2. Войти A через «Профиль»; в «Мой бизнес» выбрать существующую доступную точку.
   Перезапустить приложение: SDK восстанавливает сессию, `/me` обновляет точки.
3. Нажать «Открыть кабинет»: системный браузер открывает HTTPS `/seller`;
   отдельный вход в браузере допустим. В ссылке нет токенов/паролей.
4. В «Мал базар» добавить безличное учебное фото камерой/галереей, заполнить
   явно учебный рынок/контакт и цену за голову. Предпросмотр не публикует запись;
   после явного подтверждения и ответа сервера она появляется в «Моих» и ленте.
5. Проверить фильтр своего учебного рынка и «Есть сегодня», затем «Продано»:
   запись исчезает из public и остаётся у A со своим фото. Для «Снять» использовать
   отдельное учебное объявление и завершить его; новых реальных предложений не создавать.
6. Выйти A, войти B: «Мои»/точки/черновики A не видны. Записать результаты и
   короткое видео без экрана ввода паролей. Полный чеклист ниже и в ANDROID_ACCEPTANCE.md.

| Шаг | Ожидаемый результат |
|---|---|
| Установка 0.2.1 поверх 0.2.0/0.1.1 | Имя Qadam; тот же package; сессия/pending не очищены миграцией |
| Без входа | Мал базар открывает реальные сегодняшние объявления; доступны фильтры и карточка |
| Три нижних раздела, RU/KZ | Понятные подписи; Сегодня / Цены / Мои внутри Мал базара; нет обрезанных действий |
| Вход A через Профиль | Supabase SDK обслуживает сессию; Мой бизнес получает точки A из `/me` |
| Выбор точки | В приложении указан выбранный объект; произвольный ID ввести нельзя |
| Обновление/потеря сети | Индикатор/понятная ошибка и повтор, без подмены списком demo или нулей |
| Пользователь без membership | «Нет подключённых торговых точек»; Мал базар и публикация по-прежнему доступны |
| Открыть кабинет | Системный браузер и HTTPS `/seller`; допустим отдельный вход; в URL нет JWT/пароля |
| Выбор в кабинете | В браузере точка выбирается отдельно; выбор Flutter не обещает web-синхронизацию |
| Витрина | Отдельная кнопка открывает публичный `/`, не встроенную тяжёлую 3D-сцену |
| Возврат из браузера | Flutter работает; список membership обновляется, язык сохранён |
| Выход A, вход B | Точки/выбор/приватные экраны A исчезают, B видит только своё; повторить A → B → A при медленной сети |
| Выход в Flutter | Сессия Flutter завершена; браузерную сессию нужно завершить отдельно |
| Перезапуск | SDK восстанавливает сессию; точки загружаются заново, активная точка выбирается снова |
| Livestock | Пройти полный прежний ANDROID_ACCEPTANCE.md, включая фото, неизвестный результат, Есть сегодня и Продано |
| Маленький экран/клавиатура/крупный текст | Действия доступны через прокрутку; навигация/форма не перекрыты |

Смена API origin не переадресует старое pending-намерение автоматически. Если
результат прежнего запроса неизвестен, согласовать восстановление с backend;
не удалять локальные данные и не создавать новый ключ для той же операции.

При отсутствии отдельного учебного пользователя без membership не удалять
membership у A/B ради проверки. Отметить живой сценарий непроверенным;
автоматический fixture такого случая выполнен отдельно.

Видео 60–90 секунд: показать три раздела → точки уже авторизованного A → выбор →
системный браузер/HTTPS кабинет → возврат → Мал базар/фильтр/карточка → Профиль.
Вход и пароли записывать не нужно. Полную проверку публикации/изоляции выполнить
отдельно по таблице. Не выдавать компьютерный fixture за живую демонстрацию.

Денежные операции, AI/голос и аналитика доступны через существующий web-кабинет;
новых нативных финансовых записей или recovery-маршрутов в этом APK нет.
Фактическую смену суток фиксировать отдельно; часы общей БД не менять.
