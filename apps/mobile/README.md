# Qadam Business — Flutter

Единое приложение «Мой бизнес / Мал базар / Профиль», RU/KZ, общая тема Qadam
и существующий Supabase Auth. Текущий APK **0.3.0+6** предназначен для внутренней
приёмки. [APK, source SHA, checksum и фактические проверки](../../docs/handoffs/mobile.md).
[Короткий Android-чек-лист](docs/NATIVE_ANDROID_ACCEPTANCE.md).

Физическая приёмка **не выполнена**: Android не подключён. Все PR остаются Draft.
Моки в unit/widget-тестах не являются живым AI, микрофоном или проверкой телефона.

## Что реализовано

- «Мой бизнес»: свои точки из `/me`, серверная главная, клиенты с поиском и recovery,
  ручные продажи/доплаты, долги, история, AI-текст/голос, аналитика 7/30, заявки,
  просмотр публичного каталога. Ошибки сети не становятся синтетическими нулями.
- Новая запись: вручную или AI-черновик → проверка/редактирование → явный выбор
  клиента/продажи → предпросмотр → отдельное подтверждение. Деньги — int тиыны.
  Неизвестная оплата остаётся пустой/null, а не автоматически принятой за ноль.
- Голос: объяснение разрешения, запись, стоп на 29с, локальное прослушивание,
  отмена/удаление/перезапись. Анализ — отдельная кнопка; стоп ничего не отправляет.
  Фактический WAV PCM16 mono16kHz проверяется на <=30с и <=8MiB. Паузы нет.
- «Мал базар»: публичная сегодняшняя лента, фильтры/карточка/статистика; после входа
  фото, публикация, мои объявления, редактирование, сегодня/продано/снять.
  Цена за голову, сервер определяет сегодня. Фото идут только через FastAPI.
- «Профиль»: Supabase вход/выход. SDK обслуживает session/refresh, токены не логируются.
  Регистрация не включена; membership нужен только для CRM, не для Мал базара.
- HTTPS-кабинет остаётся в системном браузере до приёмки нативной замены. Его вход
  и выбор точки независимы; токен приложения в URL/браузер не передаётся.

## Запуск

Проверенный SDK: **Flutter 3.47.7 / Dart 3.13.5**, JDK21, Android SDK36.
Сохраните `pubspec.lock`. Добавлены только закреплённые `record 7.1.2`,
`audioplayers 6.8.1`, `http_parser 4.1.2` и их платформенные зависимости.

1. Скопируйте `config/public.example.json` в игнорируемый `config/public.local.json`.
2. Заполните только `API_BASE_URL`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`,
   `FRONTEND_BASE_URL`. Используйте согласованный publishable key, не серверный ключ.
   Постоянные адреса: API `https://qadamx-taraz.onrender.com/api/v1`,
   кабинет `https://qadamx-taraz.vercel.app`, Supabase `https://pdjjdqgoitnkpgkbqjtp.supabase.co`.
   API содержит `/api/v1`; frontend — только HTTPS origin без query/credentials.
3. Из `apps/mobile`:

```powershell
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter run --dart-define-from-file=config/public.local.json
```

Сборка с проверкой публичных полей:

```powershell
./tool/build_android.ps1 -PublicConfig config/public.local.json -Release
```

Файл: `build/app/outputs/flutter-apk/app-release.apk`. Это release-код с **внутренней
 debug-подписью**, не для магазина. Без `-Release` получается `app-debug.apk`.
Серверные ключи, DATABASE_URL, service_role, пароли, AI keys не допускаются.
Учебные пароли команда получает отдельно и вводит только на устройстве.
Без согласованного API/публичного ключа приложение честно показывает отсутствие
подключения. Production HTTPS обязателен; чужой localhost не является сервером.

## Незавершённые действия и приватность

- Отправляемый CRM intent сохраняется до POST в Keystore/Keychain по API, аккаунту,
  точке и действию. Retry использует исходные body/URL/key; другой аккаунт его не повторяет.
- `not_observed` не является отказом. CAS защищает K2 от запоздалого K1, session epoch
  блокирует ответы A→B→A. Receipt сверяется с подтверждёнными суммами/типом/клиентом.
- Не очищайте данные приложения для обхода pending: неизвестный результат требует
  восстановления или проверки команды. Незавершённый intent не сбрасывается по времени.
- Обычная ещё не отправленная форма живёт в открытом экране; durable recovery покрывает
  отправленное действие. После холодного запуска точку нужно выбрать заново.
- AI без автоматических повторов. Отмена ожидания закрывает клиент и игнорирует поздний
  ответ; она не обещает отмену обработки на сервере. Черновик не создаёт продажу.
- Аудио хранится только во временном private cache, удаляется при отмене/уходе;
  остатки после сбоя очищаются при следующем использовании. Аудио/транскрипции не логируются.
- Аналитика считается сервером; долг за всё время, поступления могут быть отрицательными,
  null среднего чека — «Нет данных». Учебная livestock-статистика может быть пустой.

## iPhone и приёмка

iOS15+ проект подготовлен, добавлены RU/KZ объяснения микрофона/камеры/галереи.
Mac с Xcode отсутствует: IPA, подпись, Keychain и физический iPhone не проверены.
[Инструкция iOS](docs/IOS_SETUP.md). Платные сервисы и App Store/TestFlight не подключались.

Проверки: 95 unit/widget PASS, analyzer clean; [APK-аудит](docs/reports/mobile-030-apk-audit.json).
Авторизованный native сценарий, реальная камера/запись/прослушивание, восстановление
после потери сети и смена суток ждут Android. Платные AI-тесты отдельно не разрешены.
Браузерный fallback сохраняется. Backend/миграции/main/production эта работа не меняет.
